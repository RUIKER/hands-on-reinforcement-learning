# DDPG 双环境经验总结

## 1. 与教程的对应关系

参考教程：[DDPG 算法](https://hrl.boyuai.com/chapter/2/ddpg%E7%AE%97%E6%B3%95)

教程的标准实验是连续动作 `Pendulum-v0`。当前实现升级为 `Pendulum-v1`，并额外提供 `CartPole` 教学适配版本。

| Case | 环境 | DDPG 动作处理 | 定位 |
| --- | --- | --- | --- |
| `Pendulum` | `Pendulum-v1` | actor 直接输出连续动作 | 标准 DDPG 实验 |
| `CartPole` | `CartPole-v1` | 连续输出映射为左右离散动作 | 教学适配，不是标准 benchmark |

## 2. Pipeline

```text
state
  -> actor(state)
  -> 确定性动作 + exploration noise
  -> 环境交互
  -> replay buffer
  -> 随机采样 batch
  -> 更新 critic
  -> 更新 actor
  -> soft update target actor/critic
```

DDPG 是 off-policy，因此可以重复利用 replay buffer 中的旧经验；这与 PPO/TRPO 的 rollout buffer 不同。

## 3. 四个网络

DDPG 同时维护：

- `actor`：输出确定性策略 `mu(s)`。
- `critic`：估计 `Q(s, a)`。
- `target_actor`：生成稳定的下一动作。
- `target_critic`：计算稳定的下一状态 Q 值。

Critic target：

$$
 y=r+\gamma Q_{target}(s',\mu_{target}(s'))(1-done)
$$

Actor loss：

$$
 L_{actor}=-\mathbb{E}[Q(s,\mu(s))]
$$

软更新：

$$
\theta_{target}\leftarrow(1-\tau)\theta_{target}+\tau\theta
$$

## 4. Normal 与 OU 噪声

DDPG 的 actor 是确定性的，如果直接执行 `actor(state)`，探索会不足。因此行为动作是：

$$
 a_{behavior}=\mu(s)+noise
$$

### Normal

```python
noise_t = sigma * N(0, I)
```

每一步独立采样，没有时间记忆。

### OU

```python
x_t = x_(t-1) + theta * (mu - x_(t-1)) + sigma * N(0, I)
```

OU 噪声具有时间相关性，偏离均值后会被拉回，教程认为它适合有惯性的物理系统。

当前通过配置切换：

```python
NOISE_TYPE = 'normal'
# 或
NOISE_TYPE = 'ou'
```

每个 episode 开始时会调用 `reset_noise()`，避免 OU 噪声把上一条轨迹的历史带入下一条轨迹。

## 5. 操作指南

以 Pendulum 为例：

```bash
cd Pendulum
python -m pip install -r requirements.txt
```

使用高斯噪声：

```python
NOISE_TYPE = 'normal'
```

使用 OU 噪声：

```python

```

```bash

```

第一次调试可以把 `MINIMAL_SIZE` 调小，先确认 replay buffer 能采样并完成一次 update，再恢复教程配置。

## 6. 结果比较方法

教程 Pendulum 参考配置大致为 200 回合，末段平均回报约 `-204.490`。比较当前实现时应保持：

- 相同环境版本。
- 相同 episode 数。
- 相同随机种子。
- 相同 actor/critic 学习率。
- 相同 replay buffer 和 batch size。
- 只改变 `NOISE_TYPE`。

建议记录：

- 最后 10 或 20 回合平均回报。
- 最佳回报。
- 回报曲线波动。
- 动作是否出现边界饱和。

Normal 和 OU 的优劣不能通过一次运行决定。OU 噪声可能带来更平滑的动作，但独立高斯噪声在许多现代连续控制实现中同样有效。

## 7. CartPole 的边界说明

标准 DDPG 需要连续动作空间，而 CartPole 的动作只有 0 和 1。当前适配器让 actor 输出一个连续值，再通过正负号选择左右动作：

```text
actor output < 0 -> action 0
actor output >= 0 -> action 1
```

critic 仍然看到连续 actor 动作，但环境实际只执行离散动作。这种环境反馈与 critic 输入之间存在量化差异，因此只能作为理解 DDPG pipeline 的教学 demo；不要把它与标准 DDPG Pendulum 结果直接比较。

## 8. 本次实验结果

使用固定随机种子，保持其他超参数不变，只切换 `NOISE_TYPE`：

| 环境 | 噪声 | 回合数 | 最后 10 回合平均回报 | 最佳回报 |
| --- | --- | ---: | ---: | ---: |
| Pendulum-v1 | Normal | 200 | `-351.685` | 约 `-11.397` |
| Pendulum-v1 | OU | 200 | `-173.886` | 约 `-0.251` |
| CartPole-v1 适配 | Normal | 500 | `13.3` | `500.0` |
| CartPole-v1 适配 | OU | 500 | `9.5` | `11.0` |

教程中的 Pendulum 参考结果是 200 回合末段约 `-204.490`。本次 OU 结果 `-173.886` 已达到相近量级，Normal 结果波动更大。一次实验不能证明 OU 永远优于 Normal，但在本次固定 seed 的 Pendulum 实验中，OU 探索表现更稳定。

CartPole 结果不能按标准 DDPG 结果解读：Normal 虽然曾经偶然得到 `500`，但末段平均只有 `13.3`，说明策略没有稳定学会；这是连续 actor 输出经过符号映射后，环境反馈被量化造成的。标准 DDPG 应优先在 Pendulum 等连续动作环境上评估。

## 9. 为什么 DDPG 曲线容易波动

DDPG 的训练回报不一定像 PPO 或 TRPO 那样平滑，主要有以下原因：

1. **训练回报包含探索噪声**：训练时执行的是 `actor(state) + noise`，即使 actor 已经学到较好的动作，噪声仍会让单个 episode 的回报上下波动。
2. **critic 误差会影响 actor**：actor 最大化 `Q(s, actor(s))`。如果 critic 的 Q 值暂时不准，actor 可能沿着错误梯度更新。
3. **DDPG 同时更新四个网络**：online actor、online critic、target actor 和 target critic 之间相互影响，对学习率、tau、噪声和随机种子都比较敏感。
4. **单次实验不能代表算法性能**：应该使用多个随机种子，观察最后若干回合平均回报，而不是只看最后一个 episode。

因此，原始回报曲线有尖峰或下降并不一定是代码错误，绘图时应重点观察移动平均曲线。

## 10. Normal 与 OU 噪声的实验建议

教程使用的高斯噪声标准差约为 `0.01`，但不同 Gymnasium 版本和随机种子下，小噪声可能导致探索不足。可以保持其他参数不变，比较：

```python
NOISE_SIGMA = 0.01
NOISE_SIGMA = 0.05
NOISE_SIGMA = 0.1
```

本次固定 seed 的 Pendulum 结果中，OU 的末 10 回合平均回报为 `-173.886`，Normal 为 `-351.685`，但这不能证明 OU 在所有 seed 下都更好。OU 可能产生更平滑的动作，而 Normal 噪声更简单、没有时间记忆。

## 11. Gymnasium 的 terminated 与 truncated

Pendulum 通常因为达到时间上限返回 `truncated=True`，这不等同于环境自然终止。

训练循环需要用两者控制 episode 是否结束：

```python
done = terminated or truncated
```

但写入 replay buffer、计算 Bellman target 时，只应把真正终止作为 terminal：

```python
terminal_for_target = terminated
```

否则每个 episode 最后一个时间截断 transition 都会错误地停止 bootstrap，增加 critic 估计误差。当前 `CartPole/trainer.py` 和 `Pendulum/trainer.py` 均已采用这种处理。

## 12. 训练回报和评估回报

训练阶段的动作包含噪声：

```python
action = actor(state) + noise
```

因此训练回报是“学习与探索的混合结果”。更可靠的评估方式是训练结束后关闭噪声：

```python
action = agent.take_action(state, explore=False)
```

当前训练曲线可以继续记录带噪声回报，但比较不同噪声或不同模型时，还应单独记录无噪声 evaluation 回报。

## 13. 稳定性实验规范

比较 Normal 和 OU 时，应保持以下条件一致：

- 环境版本。
- actor/critic 学习率。
- replay buffer 大小。
- batch size。
- gamma 和 tau。
- 训练回合数。
- 随机种子集合。

推荐使用至少 3 个随机种子，并报告最后 10 或 20 回合平均回报、无噪声 evaluation 平均回报、最佳回报，以及不同 seed 之间的均值和标准差。
