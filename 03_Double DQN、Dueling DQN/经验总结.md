# 03 Double DQN、Dueling DQN 经验总结

> **算法编号**：03 / 11
> **算法家族**：深度 value-based（离散动作）的两项改进
> **前驱算法**：02 DQN
> **后继算法**：04 REINFORCE（从价值型分支切换到策略梯度分支）
> **一句话定位**：Double DQN 修 Q 值高估，Dueling DQN 修网络结构；两者都是对 DQN 的局部补丁，不改变“离散动作 + 学 Q 值”的基本框架。

## 算法定位：四个问题

### 这个算法的特点是什么

- **Double DQN**：把 target 中的“选动作”和“评估动作”拆开。online network 选 `argmax`，target network 给该动作打分：

  $$
  a^*=\arg\max_{a'}Q_\theta(s',a'),\qquad
  y=r+\gamma Q_{\theta^-}(s',a^*)
  $$

- **Dueling DQN**：把 Q 网络拆成状态价值 `V(s)` 和动作优势 `A(s,a)` 两个分支，再合成：

  $$
  Q(s,a)=V(s)+A(s,a)-\frac{1}{|\mathcal{A}|}\sum_{a'}A(s,a')
  $$

- 两者仍然共用 DQN 的 replay buffer、target network、ε-greedy 和 MSE loss；本项目通过 `config.py` 的 `ALGORITHM` 在同一个 pipeline 内切换。

### 它针对前驱算法的哪些缺陷

- **DQN 的 Q 值高估**：target 用同一个网络既选最大动作又评估该动作，`max` 会把估计噪声也最大化。Double DQN 把选择与评估分离，降低高估。
- **DQN 把状态价值和动作优势混在一起学**：在很多状态下，不同动作的 Q 值差别很小，网络仍要花容量去学“这个状态有多好”。Dueling 显式建模 `V(s)`，让网络在动作差异小的状态上更容易学。
- **Dueling 对动作集合较大、且大量动作价值接近的情况更友好**：共享的 `V(s)` 分支不必为每个动作重复学习状态价值。

### 局限性在什么地方

- **仍然只能处理离散动作**。Pendulum 的动作被离散成 11 个力矩，天然损失精度；动作维度增大时输出层和 `argmax` 都会变贵。
- **Double 只能缓解、不能消除高估**；Dueling 不处理高估，两者解决的是不同问题。
- **本项目的 DuelingDQN 没有和 Double 组合**：它是 Dueling 网络 + 普通 DQN target，不是 Dueling Double DQN。
- **固定 ε**：当前 `EPSILON=0.01` 全程不变，缺少“先探索、后利用”的调度。
- **价值型方法的通病**：无法自然表示随机最优策略，探索靠外加 ε-greedy；样本效率仍有限。
- **离散化误差**：连续动作被切成有限档位，精细控制任务会受限。

### 典型应用场景有哪些

- 离散动作游戏、Atari 类任务，尤其是动作集合较大、状态价值占主导的场景。
- 推荐、排序、广告竞价等离散决策问题：Dueling 的 `V+A` 分解适合“选哪个动作差别不大，但状态本身好坏差异很大”的情况。
- 离散执行器控制（开关、档位、离散阀门）。
- 作为 DQN 系列的教学对照：在同一环境、同一训练循环下观察高估和网络结构的影响。

## 1. 项目目标

本项目在 `Pendulum-v1` 环境上，将连续动作空间离散化，使用 DQN 系列算法学习动作策略，并支持手动切换：

- `DQN`：普通 DQN。
- `DoubleDQN`：使用 online network 选择动作，使用 target network 评估动作，缓解 Q 值过高估计。
- `DuelingDQN`：将 Q 值拆分为状态价值 `V(s)` 和动作优势 `A(s, a)` 两部分。

项目的核心设计是：三种算法共用一套训练循环，只在 agent 内部切换网络结构或 TD target 的计算方式。

## 3. 一次交互和训练的完整流程

每个时间步大致执行以下过程：

```text
state
  -> agent.take_action(state)
  -> 得到离散动作 action
  -> dis_to_con(action) 转换为 Pendulum 连续力矩
  -> env.step(action)
  -> 得到 next_state、reward、done
  -> replay_buffer.add(state, action, reward, next_state, done)
  -> 从 replay buffer 随机采样 batch
  -> agent.update(batch)
  -> 更新 online network
```

训练不是每一步都立刻使用最新经验进行更新，而是先将经验放入 replay buffer。缓存达到 `MINIMAL_SIZE` 后，才开始随机采样 batch。这有两个好处：

1. 打散连续时间步之间的相关性。
2. 让一条经验可以被重复利用，提高样本效率。

## 4. Q 网络的含义

### 4.1 普通 Q 网络

普通网络输入状态，输出当前状态下所有动作的 Q 值：

```text
输入：state，形状 [batch_size, state_dim]
输出：Q(state, action)，形状 [batch_size, action_dim]
```

例如 `action_dim = 11` 时，网络会输出 11 个值，分别对应 11 个离散动作。选择动作时使用：

```python
action = self.q_net(state).argmax().item()
```

也就是选择预测 Q 值最大的动作。

### 4.2 Dueling Q 网络

Dueling 网络先通过共享层提取状态特征，然后分成两个分支：

```text
共享特征层
    ├── Value 分支：输出 V(s)，形状 [batch_size, 1]
    └── Advantage 分支：输出 A(s, a)，形状 [batch_size, action_dim]
```

最终使用：

$$
Q(s,a)=V(s)+A(s,a)-\frac{1}{|\mathcal{A}|}\sum_{a'}A(s,a')
$$

代码中的 `mean(dim=1, keepdim=True)` 就是在计算同一个状态下所有动作优势值的平均值。

减去平均优势值是为了避免 `V(s)` 和 `A(s,a)` 之间出现多种等价表示，从而提高训练稳定性。

## 5. 三种算法的区别

三种算法都使用：

- epsilon-greedy 选择动作。
- replay buffer。
- online network 和 target network。
- MSE loss。
- 定期同步 target network。

真正的区别如下：

| 算法 | 网络结构 | 下一状态动作的选择 | 下一状态 Q 值的评估 |
| --- | --- | --- | --- |
| `DQN` | 普通 Q 网络 | target network | target network |
| `DoubleDQN` | 普通 Q 网络 | online network | target network |
| `DuelingDQN` | Dueling Q 网络 | target network | target network |

注意：当前 `DuelingDQN` 表示“Dueling 网络 + 普通 DQN 的 target 计算”，并不是“Dueling + Double”的组合。如果需要组合版本，可以新增 `DuelingDoubleDQN`。

## 6. TD 更新逻辑

对于一个 batch，首先取出当前状态下实际执行动作的 Q 值：

```python
current_q_values = self.q_net(states).gather(1, actions)
```

`self.q_net(states)` 会输出所有动作的 Q 值，`gather(1, actions)` 只保留实际执行的动作对应的值。

### 6.1 普通 DQN 和 Dueling DQN

目标网络同时负责选择最大动作和评估该动作：

$$
Q_{next}=\max_{a'}Q_{target}(s',a')
$$

### 6.2 Double DQN

online network 只负责选择动作：

$$
a^*=\arg\max_{a'}Q_{online}(s',a')
$$

target network 再评估这个动作：

$$
Q_{next}=Q_{target}(s',a^*)
$$

这样可以将“动作选择”和“动作评估”分离，降低神经网络误差导致的 Q 值过高估计。

### 6.3 Bellman target 和 loss

最终 TD target 为：

$$
y=r+\gamma Q_{next}(1-done)
$$

如果当前 transition 已经结束，`done = 1`，则不再累加下一状态的价值。

训练 loss 为：

$$
Loss=\text{MSE}(Q_{current}, y)
$$

当前实现中，TD target 放在 `torch.no_grad()` 中计算，因为 target 只作为监督信号，不应该通过反向传播更新 target network。

## 7. Online network 和 target network

项目中有两套网络：

- `q_net`：online network，参与梯度下降，每次训练都会更新。
- `target_q_net`：target network，不直接反向传播，定期从 online network 同步参数。

初始化时先同步一次：

```python
self.target_q_net.load_state_dict(self.q_net.state_dict())
```

训练过程中每隔 `TARGET_UPDATE` 次更新再次同步：

```python
self.target_q_net.load_state_dict(self.q_net.state_dict())
```

使用延迟更新的 target network，可以避免训练目标随着 online network 每一步变化，提升训练稳定性。

## 8. 这次实现中发现并修复的问题

### 8.1 普通 Q 网络没有使用隐藏层输出

原来的写法类似：

```python
X = F.relu(self.fc1(x))
return self.fc2(x)
```

虽然计算了 `X`，但返回时仍然把原始输入 `x` 传给了 `fc2`。正确写法是：

```python
x = F.relu(self.fc1(x))
return self.fc2(x)
```

### 8.2 TD loss 变量被覆盖

错误逻辑是先计算当前 Q 值，随后又把同名变量改成 TD target，最后变成：

```python
F.mse_loss(q_values, q_values)
```

这种 loss 恒为 0，网络不能获得正确的训练信号。

现在使用不同名称区分：

```python
current_q_values = ...
td_targets = ...
dqn_loss = F.mse_loss(current_q_values, td_targets)
```

### 8.3 Dueling 网络重复计算共享层

原示例分别计算了：

```python
self.fc1(x)
self.fc1(x)
```

当前实现只计算一次共享特征：

```python
features = F.relu(self.fc1(x))
advantage = self.fc_A(features)
value = self.fc_V(features)
```

数学结果相同，但计算更清晰，也避免重复计算。

### 8.4 Gymnasium 环境版本和 API 变化

原教程使用的是旧版 Gym 和 `Pendulum-v0`。当前项目使用 Gymnasium，因此进行了以下适配：

```python
ENV_NAME = 'Pendulum-v1'
```

新版 `reset()` 返回：

```python
state, info = env.reset()
```

新版 `step()` 返回：

```python
next_state, reward, terminated, truncated, info = env.step(action)
done = terminated or truncated
```

## 11. 实验时应该观察什么

项目会记录两个主要指标：

### 回报曲线

Pendulum 的奖励通常为负数，越接近 0 越好。不能简单地把“负数”理解为训练失败，需要观察回报是否逐渐增大。

### 最大 Q 值曲线

原教程通过最大 Q 值观察过高估计问题。Pendulum 环境中理论上较好的 Q 值通常不应无限增大；如果 DQN 的 Q 值明显持续超过合理范围，而 Double DQN 更稳定，说明 Double DQN 起到了抑制过高估计的作用。

## 12. 当前实现的限制和后续改进

### 12.1 epsilon 没有衰减

当前：

```python
EPSILON = 0.01
```

整个训练过程保持固定探索概率。更常见的做法是从较大的探索率逐渐衰减到较小值，例如：

```text
epsilon: 1.0 -> 0.01
```

这样训练早期有更多探索，后期有更稳定的利用。

### 12.2 还没有实现 Dueling Double DQN

当前三种模式是独立对比。如果需要组合两种改进，可以将判断拆成两个独立配置：

```text
network_type = Qnet / DuelingQnet
target_type = DQN / DoubleDQN
```

这样可以组合出：

- 普通 DQN
- Double DQN
- Dueling DQN
- Dueling Double DQN

### 12.3 随机种子还可以进一步完善

当前设置了 Python、NumPy 和 PyTorch 的随机种子，但如果追求严格复现实验，还应在首次 `env.reset(seed=SEED)` 时设置环境种子，并根据设备情况设置 CUDA 的确定性选项。

### 12.4 需要多次实验比较

DQN 的训练结果受随机初始化、环境随机性和采样顺序影响。不要只根据一次运行结果判断算法优劣，建议使用多个随机种子，比较：

- 最终平均回报。
- 最佳回报。
- 回报达到某个阈值所需的 episode 数量。
- 最大 Q 值是否出现明显过高估计。

## 13. 总结

这个项目最重要的理解点有三个：

1. **DQN 的核心是用神经网络近似 Q 函数，并用 Bellman target 训练它。**
2. **Double DQN 改变的是下一动作的选择和评估方式。**
3. **Dueling DQN 改变的是 Q 网络结构，将状态价值和动作优势分开学习。**

当前代码已经将三种算法统一到同一个 pipeline 中，切换算法只需要修改 `config.py` 的 `ALGORITHM`，不需要复制训练代码。

## 在算法推进线上的位置

- **从哪来**：02 DQN 的 replay buffer、target network 和 TD target。
- **到哪去**：03 是价值型分支的收束。04 REINFORCE 代表另一条分支——不再学 Q 值，而是直接学策略。09 DDPG 会再次回到 DQN 的 replay + target 思想，但把它扩展到连续动作。
- **一句话记住**：Double 改的是 target 的算法，Dueling 改的是网络的形状；两者都没有跳出“离散动作 + Q 值”的框架。
