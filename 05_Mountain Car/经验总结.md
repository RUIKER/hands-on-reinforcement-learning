# 05 Mountain Car（RBF + 线性 Actor-Critic）经验总结

> **算法编号**：05 / 11
> **算法家族**：on-policy actor-critic，连续动作，线性函数逼近
> **前驱算法**：04 REINFORCE
> **后继算法**：06 Mountain Car PyTorch（同一算法的深度实现）、07 TRPO
> **一句话定位**：用 critic 的 TD error 给 actor 降方差，并用 RBF 特征 + 线性模型把低维连续控制的信用传播做得又快又稳。

## 算法定位：四个问题

### 这个算法的特点是什么

这是一个**具体的 Actor-Critic 实现**，不是 Actor-Critic 的唯一形式：

- **actor**：线性高斯策略，输出动作均值 `μ(s)` 和标准差 `σ`，动作从 `N(μ, σ²)` 采样后裁剪；
- **critic**：线性价值函数 `V(s)`，用 TD(0) 目标更新；
- **特征**：对状态做标准化，再用多组 RBF（不同 `gamma` × 分量数）展开；
- **更新**：用一步 TD error `δ = r + γV(s') - V(s)` 同时驱动 critic 和 actor；
- **关键设计**：线性模型 + 较大学习率 + 每步裁剪，让到达终点时的 `+100` 奖励能在一两次成功 episode 内沿轨迹快速回传。

与 REINFORCE 最大的区别是：actor 不再用整条轨迹的 `G_t`，而是用 critic 给出的 TD error；critic 相当于一个可自举的 baseline。

### 它针对前驱算法的哪些缺陷

- **REINFORCE 方差大**：用完整回报 `G_t` 加权，轨迹一长噪声就很大；AC 用 `δ = r + γV(s') - V(s)`，把“未来回报”交给 critic 估计，方差显著降低。
- **REINFORCE 必须等 episode 结束**：AC 可以每一步更新，适合持续/长回合任务。
- **纯价值方法难以处理连续动作**：AC 的 actor 直接输出连续动作分布参数，不需要对动作做 `argmax`。

### 局限性在什么地方

- **依赖特征工程**：RBF 的 `gamma`、分量数、scaler 都要针对任务设计；状态维度一高，分量数爆炸，这条路走不远。
- **线性表达有限**：策略和价值都只是特征的线性组合，复杂策略需要更多/更好的特征。
- **手动求导**：策略和价值的梯度公式是手推的，换分布（如 Beta 策略）就要重推，容易写错。
- **on-policy、样本效率低**：数据用一次就丢，不能像 DQN 那样反复采样。
- **探索不会退火**：`std` 按特征学习并持续增长，探索噪声始终很大，策略不会收敛到确定性；本项目成功率约 64%，曲线波动大。
- **容易陷入“do-nothing”局部最优**：到达终点前只有动作惩罚，策略可能学会“少用力、原地不动”，表现为奖励在涨但 episode 长度不降的假学习。
- **对超参数和奖励尺度敏感**：学习率、`gamma`、entropy 系数、动作裁剪方式都会改变结果。

### 典型应用场景有哪些

- 低维连续控制（MountainCarContinuous、简单倒立摆、低维机械臂）。
- 控制理论/机器人教学：actor-critic 结构、TD error、探索与信用传播的直观演示。
- 需要快速验证算法思想的 baseline：线性 + RBF 的优化是凸的、稳定的，适合做对照。
- 嵌入式或计算资源受限、状态维度低的在线控制。
- 作为 06（MLP 版）和 07（TRPO）的参照实现：保留一个“能跑通的简单版本”是调试复杂版本的前提。

本文沉淀本项目（NumPy 手动实现的 RBF 特征 + 线性 Gaussian policy actor-critic）

## 1. 本项目为什么能学会：线性模型 + 大学习率的"快速信用传播"

MountainCarContinuous 的难点不在策略表达，而在**信用传播（credit assignment）**：
到达终点前唯一的奖励是 `-0.1·a²` 的动作惩罚，+100 只在到达终点时出现一次。
一步 TD 下，价值要一个状态一个状态地回传，因此**每次更新能传播多远**决定了
算法成败。本项目的两个设计恰好都极快：

- **线性价值估计 + lr=0.1**：`Δw = lr · error · φ`。到达终点时 error≈100，
  一次更新就把终点前状态的 V 直接拉到 O(10) 量级——价值沿轨迹"一步一状态"
  地快速回传，几个成功 episode 后 advantage 就在整条轨迹上有意义。
- **线性策略 + 每次更新 clip 到 ±0.05/feature**：一次成功 episode 中几百步的
  大 advantage 会把相关特征的权重同向推很多次，策略均值在一两个成功 episode
  内就能固化出"泵动"形态。

RBF 特征（4 个 gamma × 100 分量）在 2D 状态空间上提供了良好的局部泛化：
泵动策略（随位置/速度切换推力方向）在 RBF 特征上接近线性可分，线性模型足够表达。

## 2. 迭代中修掉的 bug：truncated ≠ terminated

`step_environment` 原本把 `terminated or truncated` 合并成一个 `done`，
trainer 据此决定 `target = reward if done else reward + γ·V(s')`。
这导致 999 步时间截断时也不 bootstrap——把"人为打断"当成了"环境终止"，
每个失败 episode 的最后一步都在教 critic 错误的终态价值。

**修复**：分开返回两个 flag；只有 `terminated`（真正到达终点）才停止 bootstrap，
`truncated`（时间限制）的状态仍有价值，继续 bootstrap。

> **可复用规则**：Gymnasium 的 `terminated` 是 MDP 语义上的终止，`truncated`
> 只是时间限制。凡是自写 TD 更新，必须分开处理；直接拿合并的 `done` 做
> bootstrap 判断是 Gymnasium 迁移中最常见的隐蔽 bug。

## 3. 仍然存在的弱点（诚实记录）

- **成功率约 64%（32/50）且波动大**：曲线在 -89 和 +75 之间反复跳。原因是
  std 按特征学习且持续增长（entropy 系数 0.1 的推动 + 成功 episode 中极端动作
  的正梯度），探索噪声始终很大，策略不会退火到确定性。
- **依赖特征工程**：RBFSampler 需要先用 10k 样本拟合 scaler 和特征；换任务、
  换状态维度都要重新设计 gamma/分量数。状态维度升高后 RBF 分量数爆炸，
  这条路走不远。
- **手动求导**：policy/value 的梯度公式是手推的，换分布类型（如 Beta 策略）
  就要重推一遍，容易写错。

## 4. PyTorch (MLP+Adam) vs RBF (线性+大学习率) 核心对比

| 维度 | RBF + 线性（本项目） | MLP + Adam（PyTorch 版） |
|---|---|---|
| 价值拟合 | 凸优化，无局部最优，目标稳定 | 非凸，特征与价值共同演化，目标非平稳 |
| 单步 TD 传播速度 | **极快**（error 100 × lr 0.1，一次更新到位） | 极慢（Adam 步长≈lr=1e-3，+90 的目标需约 9 万次同向更新） |
| 逐步更新的可行性 | 可以：每步更新方向稳定、量级可控 | **不行**：Adam 二阶矩归一化把小 advantage 的噪声梯度放大到与关键步骤同量级，策略被噪声主导 |
| 梯度幅度信息 | clip 到 ±0.05/feature，保留"大 advantage → 大更新"的门控 | grad clip 到 norm 1.0 + Adam 归一化，**稀有的大 TD error 与常见小误差被抹平** |
| 奖励尺度敏感性 | 不敏感（线性 + 大 lr 直接吃掉 +100） | 敏感：+100 目标超出 MLP 快速可拟合范围，需要 reward scaling |
| 策略固化速度 | 1~2 个成功 episode | 逐步更新下 200 episode 也固化不了；改批量更新后才正常 |
| 特征工程 | 需要（RBF gamma/分量数、scaler 拟合） | 不需要，归一化到 [-1,1] 即可 |
| 可扩展性 | 高维/图像输入不可行 | 任意输入，但需要配套深度 RL 机制（批量、replay、target net、归一化） |
| 超参鲁棒性 | 教科书参数即可工作 | 对探索参数、reward scale、更新结构高度敏感 |

**一句话总结**：RBF+线性路线把"优化"变得平凡（凸、快、稳），但把成本转移到
特征工程上；MLP 路线免去特征工程，但把成本转移到优化机制上——**深度 RL 里
"神经网络 + Adam + 逐步更新"不是免费组合，批量、缩放、归一化这些机制不是
锦上添花，而是让信用传播能够发生的前提**。

## 5. 什么时候用哪种

- 状态维度低（≤ 10）、能快速拿到覆盖状态空间的样本、追求实现简单和快速验证
  算法思想 → **RBF + 线性**（教学、baseline、环境冒烟测试的首选）。
- 状态维度高、原始观测（图像/传感器序列）、或研究主题就是深度 RL 本身 →
  **MLP**，但必须接受配套机制：批量更新（或 replay buffer）、reward scaling /
  advantage normalization、（off-policy 时）target network，并把"曲线先不动"
  视为常态去排查优化链路而不是调网络结构。

## 6. 调试方法论（本次最有价值的可复用流程）

1. **先读懂曲线再动手**："奖励在涨但 episode 长度永不下降"是典型的假学习
   （do-nothing 局部最优）。两条曲线必须互相印证。
2. **给探索过程装仪表**：跟踪 std、mean|a|、到达终点次数随训练的变化。
   探索崩溃（std 单调下降）和探索棘轮（std 顶死上限）是连续动作任务的两大
   典型失败模式，方向相反但都会让学习失效。
3. **分组件验证**：critic 和 actor 分开检查——在状态网格上评估 V(s) 是否符合
   先验（越近终点越高），评估策略均值是否有合理结构。本次 PyTorch 版的问题
   就是靠"V(s) 全平"这一步定位到优化链路而非网络结构。
4. **同种子对照实验**：相同种子下改超参，如果轨迹逐位相同，说明学习对行为
   零影响（行为完全被噪声主导）——这是比 reward 曲线灵敏得多的指标。
5. **有一个能工作的参照实现**：本次所有结论都是在与 numpy 版的对照中得出的；
   保留一个"能跑通的简单版本"是调试复杂版本的前提。

## 在算法推进线上的位置

- **从哪来**：04 REINFORCE 的高方差、必须等完整 episode。
- **到哪去**：06 用 MLP + autograd 去掉 RBF 特征工程和手动求导；07 TRPO 进一步给策略更新加 KL 信任域。
- **一句话记住**：Actor-Critic 的核心不是“两个网络”，而是“用 critic 的 TD error 给 actor 降方差”；05 用线性模型把这件事做得又快又稳，代价是特征工程。
