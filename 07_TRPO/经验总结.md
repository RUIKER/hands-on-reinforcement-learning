# 07 TRPO 经验总结

> **算法编号**：07 / 11
> **算法家族**：on-policy 策略梯度，KL 信任域优化
> **前驱算法**：04 REINFORCE、05/06 Actor-Critic
> **后继算法**：08 PPO
> **一句话定位**：用 KL 散度约束新旧策略的距离，在“信任域”内最大化 surrogate objective，把“策略更新别一步走太远”从调参经验变成优化约束。

## 算法定位：四个问题

### 这个算法的特点是什么

TRPO 求解带约束的优化问题：

$$
\max_\theta \mathbb{E}_{s,a\sim\pi_{\theta_{old}}}\left[\frac{\pi_\theta(a|s)}{\pi_{\theta_{old}}(a|s)}A^{\pi_{\theta_{old}}}(s,a)\right]
\quad\text{s.t.}\quad
\bar{D}_{KL}(\pi_{\theta_{old}}\|\pi_\theta)\le\delta
$$

实现上不是直接解约束优化，而是：

1. 用 GAE 估计 advantage；
2. 计算 surrogate objective 的梯度；
3. 用共轭梯度（CG）+ Hessian-vector product（HVP）求近似自然梯度方向；
4. 按 KL 约束缩放步长；
5. 用线搜索确认目标变好且 KL 不超限；
6. 更新 actor，critic 用 Adam 拟合 `V(s)`。

它同时支持离散动作（`Categorical`）和连续动作（`Normal`），本仓库两个环境都实现了。

### 它针对前驱算法的哪些缺陷

- **普通策略梯度/AC 对步长敏感**：学习率稍大，一次更新就可能把策略推到很差的位置，而且很难恢复。
- **没有“更新幅度”的显式控制**：REINFORCE/AC 只约束梯度方向，不约束新旧策略分布的距离。
- **TRPO 的信任域**：把“新策略不能离旧策略太远”写成 KL 约束，理论上给出单调改进下界，让策略更新更安全。

### 局限性在什么地方

- **实现复杂**：需要共轭梯度、Hessian-vector product、线搜索，代码量和调试成本远高于 PPO。
- **计算昂贵**：每次更新要多次 HVP/CG；本仓库的 CartPole 和 Pendulum 训练时间都明显长于 PPO。
- **每批数据只能更新一次**：TRPO 是 on-policy，采样后做一次信任域更新就丢弃数据，样本效率低。
- **理论保证依赖近似**：单调改进结论在函数逼近、采样误差下并不严格成立；`δ`、critic 学习率、CG 迭代次数都要调。
- **对离散任务不一定更好**：本仓库 CartPole 末段 `137.700`，没有达到 `CartPole-v1` 的 500 上限；Pendulum 则接近原文量级。
- **被 PPO 取代**：PPO 用 clip 近似信任域，实现简单、可多 epoch 复用数据，实践中最常用的已是 PPO。

### 典型应用场景有哪些

- 连续控制、机器人等“策略更新稳定性优先”的任务。
- 需要可信、可解释的信任域约束的研究场景。
- 作为 PPO 的对照 baseline：理解 clip 到底近似了什么。
- 教学：自然梯度、KL 约束、HVP/CG、线搜索的完整实现范例。
- 安全关键控制（配合约束/安全层），但实际部署更多转向 PPO 或 SAC。

## 2. TRPO 的公共流程

两个版本都执行以下流程：

```text
当前策略采样完整 episode
    ↓
critic 计算 TD target 和 TD error
    ↓
使用 GAE 估计 advantage
    ↓
计算 surrogate objective 的梯度
    ↓
共轭梯度法求近似自然梯度方向
    ↓
Hessian-vector product 计算曲率
    ↓
按 KL 约束缩放更新方向
    ↓
线性搜索确认目标变好且 KL 不超限
    ↓
更新 actor 和 critic
```

TRPO 的核心约束是：

$$
\max_\theta L(\theta)
\quad
\text{s.t.}
\quad
\bar{D}_{KL}(\pi_{old}\|\pi_\theta)\leq \delta
$$

其中 actor 的更新由 KL 信任域限制，critic 使用 Adam 拟合状态价值函数。

> **Pendulum 版本（v2）与上面的流程有三处不同**：① 每收集 `EPISODES_PER_UPDATE=10` 个回合（2000 步）才更新一次，
> 单回合 200 步的批太小，梯度和 Fisher 估计都很噪；② `dones` 只记 `terminated`，回合边界另记 `ends` 用于切断 GAE，
> 时间截断处仍用 V(s') bootstrap；③ critic 回归 GAE return，做多轮 minibatch。
> CartPole 版本仍是每回合更新一次、`done = terminated or truncated`，见 §5 的说明。

## 3. CartPole 实现

CartPole 使用离散策略：

```python
probs = actor(states)
action_dist = torch.distributions.Categorical(probs)
```

策略网络输出每个动作的概率，动作通过分类分布采样。

运行：

```bash
cd CartPole
python main.py
```

## 4. Pendulum 实现

Pendulum 使用连续策略：

```python
mean, std = actor(states)
action_dist = torch.distributions.Normal(mean, std)
```

策略网络输出：

- `mean`：通过 `tanh` 映射到环境动作范围。
- `std`：通过 `softplus` 保证为正。

**动作采样后不裁剪**：`take_action` 返回策略实际采样的动作，由环境执行时自行限制到合法范围。
如果先 `clamp` 再用被裁剪的动作算 log probability，`old_log_probs` 就与实际采样分布不一致（v1 的 bug，PPO 里同样出现过，见 08 §9）。
对于一维 Pendulum 动作，策略 log probability 和 KL 散度都需要沿动作维度求和。

Pendulum 的 reward 范围通常为负数。当前实现使用：

```python
scaled_rewards = (rewards + 8.0) / 8.0
```

只对 critic 的 TD 更新进行缩放，训练日志仍记录原始 reward。

运行：

```bash
cd Pendulum
python main.py
```

### Pendulum 对比

**v1 的 `-289.503` 不再作为参考结果**：它是训练最后 10 回合的平均回报（含探索噪声），而且当时的配置有两个问题
（`KL_CONSTRAINT=5e-5` 比常用的 0.01 小约 200 倍，策略几乎不动；`take_action` 先 clamp 再算 log probability）。
在统一协议（γ=0.99）下重跑 v1，seed 1/2 全程停在随机策略水平（评估约 -1400）；γ=0.9 的 seed 0 也只有 -881，-289.5 没有复现。

v2 的改动见 §2 的说明。10 个 seed（0–9）、固定 20 个评估起始状态、确定性评估（用 `mu`），400k 步：

| 指标 | 数值 |
| --- | --- |
| 最终评估中位数 [Q1, Q3] | `-132.5` [-186.2, -131.2] |
| 最差 / 最好 seed | `-201` / `-123` |
| 最终 ≥ -200 的 seed | 9/10（s3 为 -201） |
| 首次达到 -200 的步数（中位数） | 约 90k |

TRPO 在 Pendulum 上仍比 PPO 略不稳（SAC / TD3 的 10 个 seed 全部收敛）；差距主要体现在个别起始状态上（最难的近倒挂状态摆得更慢，或个别状态失败）。
完整对比、图和逐 seed 数据见 [`../experiments/经验总结.md`](../experiments/经验总结.md)。
这套配置（KL 0.01、每批 10 回合）是在 seeds 0–2 的 3 个候选里选的，所以这三个 seed 上的数字略乐观。

Gymnasium 的 `Pendulum-v1` 与原文旧版 `Pendulum-v0` 存在版本差异，因此与原文的绝对数值不可直接比较。

### CartPole 对比

当前 `137.700` 低于原文 `200`，但两者不是完全可比的实验：

- 原文使用 `CartPole-v0`，单回合最大回报通常为 200。
- 当前使用 `CartPole-v1`，单回合最大回报通常为 500。
- 原文的 `200` 实际上同时也是旧环境的时间上限。
- 当前结果 `137.7` 表示平均能坚持约 138 步，尚未达到稳定解决任务的水平。

因此，CartPole 结果说明当前实现可以训练，但还没有复现原文中“达到回合上限”的表现。可能原因包括：

1. `CartPole-v0` 和 `CartPole-v1` 的时间上限不同。
2. Gymnasium 版本、初始化方式和环境随机性不同。
3. 当前只运行了一个随机种子。
4. TRPO 的 KL 约束、critic 学习率和线搜索参数对离散环境较敏感。
5. CartPole 训练代码使用 `done = terminated or truncated` 并把它写进 `dones`，会把 500 步时间截断当作真正终止。
   但平均 137.7 步说明大部分回合在 500 步前就已终止，截断不是主因，因此 CartPole 版本保留原写法、没有按 Pendulum v2 修改。
   Pendulum 永远不会 `terminated`，200 步截断处必须 bootstrap，所以 Pendulum 版本必须区分两者。

## 7. 后续实验建议

### 7.1 先统一比较条件

为了公平比较原文结果，可以单独建立对照配置：

- 都使用当前 Gymnasium 版本。
- 都使用明确的 episode 上限。
- 都使用相同随机种子集合。
- 都记录最后 10 或 20 个 episode 的平均回报。

### 7.2 CartPole 调参方向

可以优先尝试：

- 增大 `NUM_EPISODES`。
- 调整 `KL_CONSTRAINT`。
- 调整 `CRITIC_LR`。
- 增加共轭梯度迭代次数。
- 对多个随机种子取均值。

### 7.3 Pendulum 调参方向

Pendulum v2 已经能收敛，剩下的问题是稳定性（10 个 seed 里有几个在个别起始状态上偏慢或失败，见 `experiments/经验总结.md` §3）。可以进一步观察：

- 每次更新的实际 KL 是否经常触及约束上限（`KL_CONSTRAINT=0.01`），以及线搜索回退了几步。
- `EPISODES_PER_UPDATE`（5 / 10 / 20）对稳定性的影响；v2 选型时 5 回合的配置在 seed 2 上掉到了 -894。
- 换一批不含 seeds 0–2 的新 seed 重新确认当前配置。

## 8. 总结

这次整理的关键不是把两个环境的入口复制两份，而是明确动作空间决定策略分布：

- 离散动作使用 `Categorical`。
- 连续动作使用 `Normal`。
- TRPO 的信任域优化步骤可以复用。
- 网络输出、log probability、KL 计算和动作处理必须按动作空间分别实现。

Pendulum 的 v2 实现在统一协议下收敛到约 -132（10 个 seed 中位数）；教训是：on-policy 方法的**批大小**、**时间截断处理**和 **KL 约束的量级**
对结果的影响远大于算法本身——v1 因此得到过"TRPO 远不如 off-policy"的错误结论。
CartPole 仍需在统一环境版本和多随机种子条件下继续调参，不能仅凭一次 `137.700` 判断 TRPO 实现失败。

## 在算法推进线上的位置

- **从哪来**：04–06 策略梯度/actor-critic 对步长敏感、更新可能崩溃。
- **到哪去**：08 PPO 用 ratio clip 近似信任域，保留“别更新太远”的思想，去掉二阶优化和线搜索。
- **一句话记住**：TRPO 把“策略更新要保守”写成了 KL 约束；它证明了这件事有用，也暴露了它太贵——这正是 PPO 出现的理由。
