# 强化学习对比实验经验总结（Pendulum-v1，五算法，seeds 0–9）

协议、命令、文件索引见 [`README.md`](README.md)。图与表都在 `results/`。
第一版（3 seeds）的结论已作废，原因见 §4。

## 1. 结论

1. **五个算法最终都能解决 Pendulum**：最终评估中位数在 -121 ～ -133 之间（参考：随机策略 ≈ -1200）。
   算法之间的最终成绩差距只有几分，**不要据此排名**。
2. **算法之间真正的差别是样本效率和稳定性**：
   - 样本效率：SAC 约 5k 步达到阈值，DDPG 8k，TD3 10k；PPO / TRPO 约 90–95k（慢 10–19 倍）。
   - 稳定性：SAC 和 TD3 的 10 个 seed 都收敛；DDPG、PPO、TRPO 各有 1–4 个 seed 偏离，PPO 的 s6 没学会摆起。
3. **第一版里"PPO/TRPO 远不如 off-policy"主要是实现问题，不是算法问题**：
   旧版每 200 步更新一次、没有 minibatch、把时间截断当终止；修掉后 PPO 与 TRPO 都追到了 off-policy 的水平。
4. 墙钟：这台机器上 CPU 跑，DDPG 32 s < TRPO 42 s < TD3 50 s < SAC 68 s < PPO 72 s（含周期评估）。
   on-policy 步数多十倍，但单步便宜；对比样本效率要看 env steps，对比成本要看墙钟，两者不要混用。

## 3. 固定 seed / 固定评估状态能看出什么

- **失败不是随机的，而是集中在特定起始状态。** 固定的 20 个起始状态里，约 -0 的是靠近直立的 5 个，
  约 -125 的是 21°–122°，约 -240 的是 130°–147°（近倒挂，必须先摆起；见 `fig3`）。
  五个算法在这三档上的回报几乎一样，说明 -120 左右就是这个任务的最优量级。
- 偏离的 seed 具体栽在哪（`raw/*.json` 的 `final_eval.returns`）：
  - PPO s4、TRPO s0、DDPG s9：都只是在 **同样的两个状态**（seed 10004、10018）上失败（约 -780 ～ -900），其余状态正常。
  - TRPO s3、s6：不是失败，而是在最难的 5 个近倒挂状态上摆得更慢（约 -350 对 -240）。
  - PPO s6：20 个状态里 11 个没有摆起（约 -1100），策略停在了一个次优吸引域，整条曲线长期停在 -700。
- 因为评估状态固定，同一 seed、同一评估点上算法之间的差别不含初始状态抽样噪声；
  第一版每个评估点只用 5 个随机状态，曲线的大部分起伏其实来自"这次抽到了哪几个起始状态"。

## 4. 第一版为什么差，以及哪些结论作废

第一版（`archive_v1/`）的 PPO 最终 -593、TRPO -1403。对照实验把问题定位到 PPO/TRPO 的实现，改动如下：

| 问题 | 旧版 | 现版 |
|---|---|---|
| 更新批大小 | 每 1 个回合（200 步）更新一次，全批 10 轮 | 每 10 个回合（2000 步）更新一次，minibatch 64 |
| 时间截断 | `dones = terminated or truncated`，200 步处不 bootstrap | `dones` 只记 terminated；回合边界用 `ends` 切断 GAE，截断处用 V(s') bootstrap |
| advantage | 不归一化 | minibatch 内归一化；critic 回归 GAE return |
| 稳定性 | 无梯度裁剪 | 梯度裁剪 0.5；λ=0.95 |
| TRPO 动作 | `take_action` 先 clamp 再算 log_prob（与 PPO 已修的 bug 相同） | 保存实际采样动作 |
| TRPO 信赖域 | `KL_CONSTRAINT=5e-5`（小约 200 倍，策略几乎不动，seed 1/2 全程停在随机水平） | `0.01` |

旧版临时对照（单变量）：只修截断，PPO 仍有 -595 / -617；只加 advantage 归一化更差；
**成批更新才是关键**。新版代码在 `08_PPO/Pendulum`、`07_TRPO/Pendulum`，旧版在各自 `legacy_v1/`。

作废的结论：

- "γ=0.99 会让 PPO 退化 / 超参是按 γ=0.9 调的"：不成立。新版 γ=0.99 下 PPO 正常；这个现象是批太小 + 截断处理造成的。
- "驱动层正确（-338.2 对仓库 -338.146）"：口径不同——仓库数字是训练最后 10 回合均值，不是确定性评估，对上只是巧合。
- "PPO 245k 对 SAC 5k"：旧版 steps-to-90% 的阈值按各组自己的最好成绩算，两组比的不是同一条线。现版用固定绝对阈值 -200。
- "文档预期的 SAC 20k ≈ PPO 400k 没有复现"：现版 PPO 在约 95k 步就达到 -200，样本效率差约 10–19 倍；
  是否"差一个数量级"取决于阈值，请引用具体数字而不是这句话。

## 5. 其他经验

- **同一 seed 在不同设备上不复现同一条轨迹。** 第一版在 CUDA 上跑出的 DDPG s0 为 -545（中途崩掉），
  现在 CPU 上同一个 seed、同一份配置是 -126。我曾怀疑是 `NOISE_SIGMA=0.01` / `BUFFER_SIZE=1e4` 的问题，
  对照后（σ=0.1、buffer=1e5 在 3 个 seed 上与原配置无差别）**这个怀疑没有被证实，所以没有改 DDPG 的配置**。
  更稳妥的说法是：DDPG 对训练轨迹敏感（现版 10 个 seed 里仍有 s9 = -205，且多数 seed 在训练中途出现过掉坑）。
  跨设备比较或复现旧结果时，不要期望 seed 对得上。
- **调参的诚实性**：PPO 用的是诊断时验证过的一组配置（没有扫描）；TRPO 在 3 个候选
  （KL 0.01 × 每批 10 回合 / KL 0.01 × 5 回合 / KL 0.02 × 5 回合）里按 seeds 0–2 的结果选了第一个。
  这些 seed 与最终报告重叠，见 §2 末尾的说明。
- **设备**：这些网络很小（3→128→1），瓶颈是 kernel 启动和 CPU↔GPU 同步，不是算力。
  CPU 跑 on-policy 400k 步只要 30–70 s；旧版在另一台机器的 GPU 上要 350–420 s（跨机器，不是同机对照，只说明量级）。上 MuJoCo 之后再考虑 GPU / vectorized env。
- **性能优化（数值等价、只提速）**：去掉热路径的 `.item()`（TD3 每步一次）、缓存动作边界（DDPG 每步两次同步）、
  软更新改 `torch._foreach_*`。fused Adam 和 `torch.compile` 不保证逐位一致；若报告墙钟，所有 seed 必须用同一版代码重跑。
  不要为了"提高 GPU 利用率"增大 batch、降低更新频率或换并行环境——那会改变算法本身，曲线不再可比。
- **不要过度解读 n=10**：能看分布形状和失败模式，仍不做显著性检验；TD3 / SAC / DDPG 的中位数差 1–5 分，不要排名。
  Pendulum 不是公认 benchmark，这套协议的价值是为 MuJoCo / Meta-World 复用。

## 6. 局限与下一步

- 预算不对等（40k vs 400k）是有意的：为的是比"达到同一水平需要多少步"。若要比同预算下的最终成绩，需要把 off-policy 也跑到 400k（SAC 约 10 倍时间，仍在分钟级）。
- PPO s6 的"卡在次优吸引域"没有深挖（是探索不足、初始 std 偏小，还是 critic 误导），可以固定 s6 做单变量对照。
- TRPO 目前是 3 个配置里选的，若要作为正式对照，应该在不含 seeds 0–2 的新 seed 集上重新确认。
- 下一步：把同一协议搬到 HalfCheetah / Hopper；`results/models/` 里的 actor 权重可直接用于鲁棒性 / 扰动实验。
