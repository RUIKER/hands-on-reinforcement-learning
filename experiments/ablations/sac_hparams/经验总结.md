# SAC 超参单因素扫描经验总结（HalfCheetah-v5，100k × 3 seeds）

协议和命令见 [`README.md`](README.md)，数据在 `results/`。
基线是 `seed_experiments/halfcheetah_sac` 的 1M 结果在 20k 评估网格上的前 100k 步（同代码、同 seed）。

## 1. 结论（按证据强度分三档）

**A. 机制已验证**

1. **初始 alpha 1.0 只造成一段约 20–25k 步的延迟，不是长期劣势。** 诊断（§4）显示它的 alpha 在 10k 次更新内从 1.0 衰减到 0.06，
   期间策略熵远高于目标、动作均值接近 0；到 30k 步 alpha 回到和基线同一个量级（约 0.01）。

**B. 方向一致、幅度大，值得相信（但 n=3，机制只部分验证）**

2. **gamma 0.95 明显更差**：3 个 seed 都低于基线，配对差 -2670（-55%），p≈0.016（未校正）。
   但它不是“整体低一截”：s2 在 100k 追到 5107，s0/s1 还停在 1576/2265，更像是**不同 seed 发现跑步步态的时间被推迟且不一致**。
3. **lr 1e-4 明显更慢**：3 个 seed 都低于基线，配对差 -1777（-37%），p≈0.031。它在 100k 的水平约等于基线在 ~56k 步的水平
   （线性插值，约慢 1.8 倍，而不是学习率比值 3 倍）。

**C. 无法区分，不要解释**

4. **lr 1e-3**（+6%）、**batch 64**（-17%）、**batch 1024**（-11%）：配对差 t 分别为 0.70 / -1.22 / -1.56，p 均 > 0.25，
   且各只有 2/3 个 seed 同号。**这三项在 100k 步、3 seeds 下和基线分不开。**
   唯一的亮点是 lr 1e-3 的**早期**优势（§3.2），但终点看不出。

> p 值只是量级参考：n=3（df=2）、6 个配置同时比较未做多重比较校正。Bonferroni（×6）后 gamma 0.95 约 0.10、lr 1e-4 约 0.19，
> 都不过 0.05。所以 B 档是“强线索”，不是“已证明”。

## 3. 为什么相对基线会变成这样

共同背景：**每个 env step 做 1 次更新（更新/数据比固定为 1）**，所以任何超参的影响都通过“每次更新走多远、走得多准、
优化的目标是什么”三条路进来。基线在 100k 步时还在爬坡（1M 才到 ~11k），所以这里比的是**上升速度**，不是终点。

### 3.1 lr 1e-4：每次更新走得太短（B 档）

- 观察：整条曲线向右平移，20k/40k 时仍在 0 附近（20k 处 60/-219/-251），100k 才到 ~3900。
- 机制：critic 要把 Q 值从 0 学到几十到几百，actor 要跟着 Q 变；步长缩小，两者都变慢。
  Adam 的有效步长约等于学习率，所以更新次数不变时，走过的距离更短。
- 为什么只慢 ~1.8 倍而不是 3 倍：Adam 的步长并不严格和学习率成正比（梯度方向一致时有效步长更大）。这是对插值结果的解读，**没有单独验证**。
- 没有证据的部分：1M 时它是否追平。慢不等于差，这里没有 1M 数据。

### 3.2 lr 1e-3：早期更快，终点分不开（C 档，但早期有信号）

- 观察：20k+40k 的均值 2266 vs 基线 1501（+51%）；40k 处 3 个 seed 全部高于基线；20k 处 3 个 seed 里 2 个高于基线（s2 的 614 < 884）。
  到 100k 配对差只剩 +284，s2 反而低于基线（-442）。
- 解释（推断）：大步长在“表还很粗糙”的阶段收益大，等 Q 和策略接近各自的局部最优后，大步长带来更大的噪声，优势被吃掉。
- 要验证需要更长预算（1M）或观察训练中 Q 的震荡；这里都没有。**不要据此说 1e-3 更好。**

### 3.3 batch size：非单调，且没有统计差异（C 档）

- 纸面预期：更大的 batch 梯度噪声更小 ⇒ 1024 ≥ 256 ≥ 64。
- 观察：64 与 1024 都低于基线，且 batch 64 在 60k 处有两个 seed 掉回 1178/2690（一次评估只有 5 回合，单点噪声可到 ~1000）。
- **预测与结果不符，如实记下**：1024 没有更好。可能是噪声，也可能是“固定更新次数下，大 batch 每步更稳但并没有多学到东西”。
  现有数据不能区分这两种解释，所以不选。
- 侧面观察：6 个配置并行时单 run 耗时几乎相同（1960–2100 s，batch 1024 也不更慢）。说明这台机器上瓶颈是 kernel 启动/CPU 调度而不是矩阵计算量，
  “大 batch 单步更贵”在这里不成立，不能拿它做取舍依据。

### 3.4 gamma 0.95：视野从 5 秒缩到 1 秒（B 档）

- 观察：3 个 seed 都明显低于基线，但内部很散：1232 / 1941 / 3291，s2 在 80k→100k 从 2566 跳到 5107。
- 机制（推断，未验证）：γ=0.95 的有效视野是 1/(1-γ)=20 步 = 1.0 s（γ=0.99 是 100 步 = 5.0 s，控制步长 0.05 s）。
  HalfCheetah 的 reward 是前进速度减控制代价，每步都有稠密信号，所以并不是“看不到回报”；更可能是**需要跨多步协调才能形成的周期性步态**，
  在短视野下 Q 对“现在多花力气、几步后才变快”的动作估值偏低，更容易停在低速/不稳的局部步态。
- 两处没验证：(1) 没有看策略的实际行为（视频、躯干姿态、x 速度）；(2) 没有控制 γ 同时改变的 Q 量级（Q ≈ r/(1-γ)，γ 小时 Q 小很多，
  温度和 Q 的相对尺度也变了）。**这是两个混杂因素，现在无法拆开。**
- s2 的跳变说明它更像“发现步态的时间点”而不是“稳态水平”——“更差”和“更不稳定”不是二选一，3 个 seed 区分不了。

## 4. alpha 诊断（`diagnose_alpha.py`，seed 0，只跑 30k 步）

| 步数 | 基线（init 0.01）：alpha / 熵 / mean\|tanh μ\| / Q | init 1.0：alpha / 熵 / mean\|tanh μ\| / Q |
| ---: | --- | --- |
| 11k（1k 次更新后） | 0.0094 / -7.75 / 0.78 / 0.9 | 0.74 / 4.04 / 0.10 / 14.5 |
| 15k | 0.0129 / -6.42 / 0.70 / 3.3 | 0.23 / 3.37 / 0.31 / 31.6 |
| 20k | 0.0137 / -5.88 / 0.70 / 6.9 | 0.057 / -0.31 / 0.58 / 28.9 |
| 25k | 0.0147 / -6.13 / 0.68 / 11.5 | 0.017 / -4.90 / 0.69 / 25.8 |
| 30k | 0.0213 / -5.88 / 0.69 / 18.4 | 0.0097 / -6.28 / 0.66 / 20.9 |

读法：

- **基线（alpha=0.01）**：更新一开始熵就从 2.75 掉到 -7.75（低于目标 -6），动作均值立刻变大（0.29→0.78）；之后 alpha 缓慢上升到 0.02，熵稳定在目标附近。
  也就是说 **0.01 对这个任务是偏小的初值**——策略几乎立即变窄，靠 alpha 自动调节慢慢拉回。
- **init 1.0**：log alpha 每步最多改约一个学习率（3e-4），从 1.0 降到 0.1 至少需要 ~7.7k 步更新，实测 10k 次更新降到 0.057。
  这段时间熵一直在 3–4（目标 -6），`mean|tanh μ|` 只有 0.1–0.3。**确定性评估用的是 tanh(μ)，策略均值接近 0 就等于“几乎不动”**，
  这就是 20k 步时 3 个 seed 都是负回报（-195/-353/-68）的原因。
- 同一时期 Q 被熵奖励垫高（Q 峰值 31 vs 基线 3.3）：soft Bellman 目标里的 `−α·logπ` 在 α 大时占很大比重，Q 学到的是“熵的价值”而不是“速度的价值”；
  α 降下来后 Q 还要被重新拟合（31→21）。
- 到 25–30k，alpha、熵、动作均值都和基线重合。**所以 init alpha 的影响是暂时的，约 20–25k 步。**
- 自洽性检查（不是证明）：基线在 60k–100k 的斜率约 24 回报/千步；延迟 ~20k 步 ≈ 少 ~480，而实测配对差是 -483。

诊断的局限：只有 seed 0；探针在回放缓冲区的 512 个状态上测；没有其他 seed 重复。

## 5. 这份实验做得怎么样

**可信的部分**

- 基线与扫描是同代码、同默认值、同 seed、同评估网格（评估初始状态相同），逐点可比。
- 同一个 seed 的初始网络相同，且前 10k 步只采样不更新，所以理论上各配置的起始数据相同（没有逐条核对 buffer），配对比较比独立比较更紧。
- alpha 的结论有机制诊断支撑，不是只看曲线。

**不可靠 / 受限的部分**

1. **n=3、df=2**：p 值只能当量级参考；6 个配置未做多重比较校正。真正稳的只有“同号 3/3 且幅度大”的两项。
2. **100k 不是终点**：基线 1M 才约 11k，100k 看的是上升速度，不能把排序外推到最终性能。
3. **单点评估噪声大**：每点 5 回合，单点可差 ~1000；用 60k/80k/100k 三点均值缓解，没有消除。
4. **单因素扫描**：看不到交互（lr×batch、γ×alpha、reward scale×alpha）。γ 的结论尤其受 Q 尺度混杂。
5. **一个环境、一个实现**：这是 HalfCheetah 上这份 SAC 实现的结论，不是“SAC 的结论”。
6. **没有看策略行为**：所有“步态”相关的说法都是推断。
7. **只用确定性 tanh(μ) 评估**：对初始 alpha 这种改变策略方差的超参，确定性评估会放大“早期不动”的现象（见 §4），随机策略的回报可能不同。

## 6. 回答之前留的三个问题

1. **“lr 1e-3 的 +6% 在 1 个 std 内，算不算结论？”** 不算。配对 t=0.70，p≈0.56。但它的**早期**优势（20k+40k +51%，40k 处 3/3 seed）是一个独立的、值得继续看的信号。
2. **“100k 时好几个配置收敛到 5000 左右，说明什么？”** 先纠正：**那不是收敛**。基线 1M 才到 ~11k，5000 左右只是上升途中的同一高度；
   差异出现在 40k–80k，说明超参改变的是“何时到达”，不是“到达哪里”。
3. **“gamma 0.95 的 std 是基线两倍多，是均值更差还是更不稳定？”** 两者都有，3 个 seed 区分不了：均值低、且 s2 在最后一个区间突然追上，更像“发现步态的时间点”变散。要区分需要更多 seed 或看行为。

## 7. 下一步（按性价比）

1. 基线和扫描都补到 5 seeds（agent 可做，约 4 小时 GPU），先看 C 档结论会不会变。
2. lr 1e-3 和 lr 1e-4 各补 1M × 3 seeds：回答“早期快、晚期是否反而差”。
3. γ 0.95 保存策略，看视频和躯干姿态，验证“局部步态”的推断（你自己做更有收获）。
4. alpha 初值对齐 SB3（默认 1.0）不一定更好——§4 说明它换来的只是 ~20k 步延迟；可做 `reward_scale × alpha` 联动实验。

## 8. 面试一句话

“我在 HalfCheetah 上做了 SAC 的单因素超参扫描：100k 步时学习率 1e-4 和 γ=0.95 明显更慢；
初始温度 1.0 只造成约 20k 步的暂时延迟，我用 alpha、熵、动作均值的轨迹验证了机制；
而 batch size 和更大的学习率在 3 个 seed 下与基线分不开，所以我没有下结论。”
