## 本案例中的四个问题

### 这个算法的特点是什么

在 Pendulum 上，DDPG 用确定性 actor 输出一个力矩，critic 估计 `Q(s,a)`，replay buffer 反复利用旧 transition，target 网络软更新。训练时在动作上加 Normal/OU 噪声探索，评估时关闭噪声。

### 它针对前驱算法的哪些缺陷

它把 DQN 的 replay + target network 搬到连续动作空间，解决 DQN 只能 `argmax` 离散动作的问题；同时用 off-policy 复用数据，缓解 PPO 等 on-policy 方法样本效率低的问题。

### 局限性在什么地方

本案例中 DDPG 的训练回报波动明显（3 个种子末 10 回合 `-206.7 ± 25.7`），对噪声类型、`γ`、学习率和随机种子都敏感；单个 critic 无法抑制 Q 值高估，探索噪声固定为 `0.01` 时探索偏弱。这些正是 TD3 的改进动机。

### 典型应用场景有哪些

低维连续控制的教学与 baseline、机械臂/倒立摆类任务、需要 off-policy 样本复用的连续动作场景。高维或对稳定性要求高的任务应优先考虑 TD3/SAC。

## 1. DDPG 的核心结构

DDPG 是 off-policy 的确定性 actor-critic 算法，包含四个网络：

```text
actor          mu(s)
critic         Q(s, a)
target_actor   mu_target(s)
target_critic  Q_target(s, a)
```

Critic 使用 Bellman target：

$$
y=r+\gamma Q_{target}(s',\mu_{target}(s'))(1-done)
$$

Actor 的目标是让 critic 评价当前策略动作更高：

$$
L_{actor}=-\mathbb{E}[Q(s,\mu(s))]
$$

Target 网络不直接通过梯度更新，而是使用软更新：

$$
\theta_{target}\leftarrow(1-\tau)\theta_{target}+\tau\theta
$$

## 2. Replay buffer

DDPG 是 off-policy 算法，使用长期 replay buffer：

```text
与环境交互
  -> 保存 (s, a, r, s', done)
  -> 随机采样 batch
  -> 更新 critic
  -> 更新 actor
  -> 软更新 target 网络
```

旧经验仍然可以被当前策略重复利用，这是 DDPG 样本效率高于 REINFORCE/PPO 的原因之一。

## 3. Normal 和 OU 探索噪声

DDPG 的 actor 是确定性策略，若直接执行 `actor(state)`，探索不足，因此在行为动作上增加噪声：

$$
a_{behavior}=\mu(s)+noise
$$

### Normal 噪声

每一步独立采样：

$$
noise_t=\sigma\epsilon_t,\quad \epsilon_t\sim\mathcal{N}(0,I)
$$

特点是简单、无时间相关性。

### OU 噪声

实现为：

$$
x_t=x_{t-1}+\theta(\mu-x_{t-1})+\sigma\epsilon_t
$$

OU 噪声会把偏离均值的噪声拉回去，因此连续动作在时间上更平滑，适合具有惯性的物理系统。当前代码通过 `config.NOISE_TYPE` 手动切换：

```python
NOISE_TYPE = 'normal'
# 或
NOISE_TYPE = 'ou'
```

## 4. Pendulum pipeline

- `config.py`：学习率、软更新系数、噪声类型和 replay buffer 配置。
- `environment.py`：创建 `Pendulum-v1` 并读取动作上下界。
- `networks.py`：定义 actor 和 critic。
- `noise.py`：实现 Normal 和 OU 噪声。
- `agents.py`：实现 DDPG 更新和 target 网络软更新。
- `trainer.py`：执行 off-policy 交互和采样更新。
- `rl_utils.py`：实现 replay buffer。
- `main.py`：运行入口。

## 5. 操作指南

进入目录：

```bash
cd Pendulum
```

安装依赖：

```bash
python -m pip install -r requirements.txt
```

使用独立高斯噪声：

```python
NOISE_TYPE = 'normal'
```

使用 OU 噪声：

```python
NOISE_TYPE = 'ou'
```

运行：

```bash
python main.py
```

第一次调试时可以把 `NUM_EPISODES` 降低，并把 `MINIMAL_SIZE` 调小，确认 replay buffer、动作形状和一次 update 都正常后再恢复正式配置。

## 6. 实验比较建议

比较 Normal 和 OU 时，应保持以下参数一致：

- 随机种子。
- episode 数量。
- actor/critic 学习率。
- replay buffer 大小。
- batch size。
- gamma 和 tau。

建议记录：

- 最后 10 或 20 个 episode 平均回报。
- 最佳 episode 回报。
- 回报曲线的波动程度。
- 动作序列是否更平滑。

单次运行不能证明哪种噪声一定更好。OU 噪声在有惯性的环境中可能更平滑，但现代实践中独立高斯噪声也经常表现良好。

## 在算法推进线上的位置

- **从哪来**：02 DQN 的 replay buffer + target network，以及 04–08 策略梯度分支的连续动作经验。
- **到哪去**：10 TD3 针对本案例暴露的训练波动、单 critic 高估和 target 尖峰做三项改进。
- **一句话记住**：DDPG 在 Pendulum 上能学，但训练回报方差大；这正是 TD3 的出发点。
