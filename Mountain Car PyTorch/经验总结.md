# Mountain Car (PyTorch MLP Actor-Critic) 经验总结

本文沉淀本项目（PyTorch MLP + autograd + Adam 的 actor-critic）从"输出明显不对"
到真正学会 MountainCarContinuous 的完整迭代过程与可复用经验。

## 1. 迭代时间线：从假学习到真学习

| 阶段 | 配置要点 | 结果（同种子） | 教训 |
|---|---|---|---|
| 原始版本 | tanh 压缩、std 初值 0.61、entropy 1e-3、逐步一步 TD、γ=0.99 | **0/200 到达终点**，奖励 -21→-5 后走平 | 曲线"在涨"≠在学 |
| 探索修复 | clip 动作、std 初值 1.0、entropy 1e-2、γ=0.95、truncation bootstrap | 21/200，但始终靠运气，无固化趋势 | 能探索到 ≠ 能学到 |
| 结构修复 | 上条 + episode 批量更新 + 5 步回报 + reward scale 0.01 | **86/200，最后 50 轮 46/50，步数降至 200~500** | MLP 的信用传播要靠更新结构保障 |

## 2. 三个层次的 bug（按发现顺序）

### Bug 1：truncated 被当作终止（与 numpy 版共有）

`terminated or truncated` 合并后用于 bootstrap 判断，999 步时间截断时
TD target 不含 `γ·V(s')`。本任务中**每个** episode 都以截断结尾，等于每轮
结尾都在污染价值函数。

> 规则：`terminated`（MDP 语义终止）才停止 bootstrap；`truncated`（时间
> 限制）必须继续。这是 Gymnasium 迁移中最常见的隐蔽 bug。

### Bug 2：探索机制永远到不了终点

原始版本 tanh 压缩 + std≈0.61 的零均值高斯探索是小幅抖动，无法形成持续泵动。
同时到达终点前唯一奖励信号是 `-0.1·a²`，梯度把动作和 std 一起压向 0
（实测 std 从 0.61 单调降到 0.24），策略收敛到"谷底不动"的局部最优——
这就是 -21→-5 这条**假学习曲线**的本质：它只是在学"少用力"。

修复：clip（产生 ±1 饱和的 bang-bang 动作，是摆上山的关键）、std 初值 1.0、
entropy 系数 1e-2。对照实验：tanh 0/60 到达，clip 10/60 到达。

### Bug 3：逐步更新 + MLP + Adam 的结构性失效（最深层）

探索修复后能碰到终点了，但学习依然不发生。逐组件排查发现：

- **critic 是一条 ≈-1.6 的平线**（应在终点附近 ≈+90）。grad clip 到 norm 1.0
  把 +100 的 TD error 与 ±0.1 的普通误差裁成同等大小的更新；Adam 的步长
  ≈lr，拟合 +90 量级的目标需要约 9 万次同向更新——稀有的大信号被 19 万步
  小信号彻底淹没。
- **std 棘轮效应**：policy gradient 中，到达终点的都是 |a-μ|>σ 的极端动作，
  它们的 advantage 为正 → log_std 的梯度恒正 → std 一路顶到 clamp 上限 2.72，
  行为完全被噪声主导。
- **判决性实验**：同种子下换 actor lr（3e-4/1e-3/3e-3）、critic lr、reward
  scale、优化器（Adam/SGD）等 10 组配置，**轨迹逐位相同**——学习对行为零影响。

修复：**episode 结束后批量更新 + n 步回报 + reward scale**。批量平均降梯度
方差（棘轮消失，std 稳定在 1.05）；n 步回报把 +100 一次回传 n 步；reward
scale 0.01 让 critic 目标值保持 O(1)。修复后 V(s) 呈现出正确结构（越近终点、
速度越大，V 越高），策略均值学出随速度调制的泵动形态。

## 3. PyTorch (MLP+Adam) vs RBF (线性+大学习率) 核心对比

| 维度 | MLP + Adam（本项目） | RBF + 线性（numpy 版） |
|---|---|---|
| 免特征工程 | ✅ 归一化即可 | ❌ 需拟合 scaler + 设计 gamma/分量数 |
| 表达任意策略/价值 | ✅（理论上） | 低维够用，高维不可行 |
| 逐步 TD 的价值传播 | **极慢**：Adam 步长≈lr，+90 目标需约 9 万步 | **极快**：error×lr×φ 一次更新到位 |
| 梯度幅度信息 | grad clip + Adam 归一化会**抹平**大小信号差异 | clip 到 ±0.05/feature 仍保留门控 |
| 探索与学习的竞赛 | 均值学得慢 → std 棘轮先赢 → 噪声主导 | 均值 1~2 个成功 episode 即固化 → 学习先赢 |
| 奖励尺度 | 敏感，需要 reward scaling | 不敏感 |
| 超参鲁棒性 | 更新结构/探索/缩放都要对才行 | 教科书参数即可 |
| 最终性能（本任务） | 92%（后 50 轮），步数 200~500 | 64%（50 轮），波动大 |

**一句话总结**：numpy 版把成本花在特征工程上，换来平凡（凸、快、稳）的优化；
本项目把成本花在优化机制上，换来免特征工程和可扩展性。**深度 RL 中"神经网络
+ Adam + 逐步更新"不是免费组合——批量、reward scaling、归一化不是调优技巧，
而是让信用传播得以发生的前提条件。**

## 4. 可复用清单（迁移到其他连续控制任务）

1. 分离 `terminated` / `truncated`，截断必须 bootstrap。
2. 连续动作用 **clip 而非 tanh**（或至少验证探索能到达关键区域）；监控 std
   轨迹，既要防崩溃（→0）也要防棘轮（→上限）。
3. 稀疏大奖励 + 稠密小惩罚的任务里，先检查"do-nothing 局部最优"：曲线在涨
   但 episode 长度不降 = 假学习。
4. MLP critic 遇到 +100 量级目标时：reward scaling 到 O(1)，统计输出仍记
   原始奖励，保持曲线单位可比。
5. 逐步 on-policy 更新 + Adam 学不动时，优先改**更新结构**（批量/n 步），
   而不是调 lr——Adam 的归一化会让 lr 在一定范围内失效。
6. 同种子对照实验是灵敏度最高的诊断：改配置后轨迹逐位相同 = 学习未影响行为。
7. 分组件验证：在状态网格上评估 V(s) 与策略均值，比盯着 reward 曲线猜
   要高效得多。

## 5. 已知边界

- episode 批量更新牺牲了在线性（每轮结束才学一次）；对长 horizon 任务可改
  为每 N 步滚动批量更新（标准 A2C 的 n-step rollout）。
- on-policy actor-critic 样本效率仍低；更进一步是 replay buffer + off-policy
  （DDPG/SAC 方向），但那已超出本项目作为课程对照的范围。
