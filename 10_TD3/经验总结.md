# 10 TD3 经验总结

> **算法编号**：10 / 11
> **算法家族**：off-policy、确定性 actor-critic（连续动作）
> **前驱算法**：09 DDPG
> **后继算法**：11 SAC（同代兄弟：TD3 修稳定性，SAC 换最大熵框架）
> **一句话定位**：不改变 DDPG 的确定性 actor 结构，只用“双 Q 取最小、target 动作加噪、延迟更新”三个补丁，把 DDPG 从“能学但脆”变成“能稳定学”。

## 算法定位：四个问题

### 这个算法的特点是什么

TD3 在 DDPG 上做三项改动：

1. **Clipped double-Q**：两个独立 critic，Bellman target 取最小值：

   $$
   y=r+\gamma(1-d)\min_{i=1,2}Q_{\phi_{i,\text{targ}}}(s',a')
   $$

2. **Target policy smoothing**：给 target actor 的下一动作加截断噪声：

   $$
   a'=\operatorname{clip}\left(\mu_{\theta_{\text{targ}}}(s')+\operatorname{clip}(\epsilon,-c,c),a_{Low},a_{High}\right)
   $$

3. **Delayed policy update**：每更新 `policy_delay` 次 critic，才更新一次 actor 和 target 网络。

其余部分与 DDPG 相同：replay buffer、target network、软更新、确定性 actor、外加高斯探索噪声。

### 它针对前驱算法的哪些缺陷

- **DDPG 的 Q 值高估**：单 critic 的 `max` 自举会把噪声也最大化；TD3 用双 Q 取最小，给出保守估计。
- **DDPG 的 target Q 尖峰**：target 动作只有 `μ_target(s')` 一个点，critic 可能在附近产生错误高 Q；target smoothing 让 critic 在动作附近一小片区域都给出相近值。
- **DDPG 的 actor 更新过于频繁**：critic 还没学好，actor 就跟着不准确的 Q 更新；延迟更新让 critic 先学两步，actor 再动。

### 局限性在什么地方

- **仍然是确定性策略**：探索靠外加噪声，噪声尺度需要调；没有 SAC 那样的熵正则和原则性探索。
- **两个 critic + 两个 target critic**：计算和显存成本约为 DDPG 的两倍。
- **仍然 off-policy、非凸**：没有收敛保证；对学习率、`τ`、`policy_delay`、噪声参数仍敏感。
- **只适用于连续动作**：离散动作仍需 DQN 系列或离散 SAC。
- **不是万能药**：在 Pendulum 这类简单任务上，TD3 的最终确定性评估与 DDPG 接近（本仓库 `-124.9` vs `-126.9`），优势主要体现在训练稳定性和跨种子方差；在更难的高维连续控制任务上差距才明显。
- **target smoothing 的单位容易写错**：噪声按归一化动作定义时，必须乘 `action_scale` 换算到环境动作单位。

### 典型应用场景有哪些

- 连续控制中 DDPG 训练不稳定的场景：locomotion、机械臂、操作任务。
- 机器人仿真到现实、自动驾驶低层控制、工业连续控制。
- 需要比 DDPG 更稳、又不想引入 SAC 的随机策略和额外超参数的场景。
- 作为 DDPG 的对照：固定其他超参数，只切换三项改进，观察 Q 值和回报曲线。
- 教学：理解“双 Q、smoothing、延迟更新”三个补丁各自解决什么。

## 1. TD3 要解决什么问题

TD3（Twin Delayed DDPG）是 DDPG 的直接改进版。DDPG 在连续控制中很有效，但训练容易不稳定，主要原因是：

1. **Q 值高估**：critic 用 TD target 自举，函数逼近误差和最大化操作会让估计的 Q 值系统性偏大。actor 又会去最大化这个偏大的 Q，形成正反馈。
2. **确定性 target 动作的尖峰**：DDPG 的 target 动作是 `mu_target(s')`，只有一个点。critic 可能在这一点附近产生错误的高 Q 尖峰，actor 会利用这个错误。
3. **actor 更新过于频繁**：critic 还没学好，actor 就跟着不准确的 Q 更新，容易把策略带偏。

TD3 对应给出三项改进：clipped double-Q、target policy smoothing、delayed policy update。三者缺一不可，论文的消融实验也是逐项叠加的。

## 2. 三项核心改进

### 2.1 Clipped double-Q

TD3 训练两个独立初始化的 critic `Q1` 和 `Q2`，以及对应的 target critic。Bellman target 使用二者最小值：

$$
y=r+\gamma(1-d)\min_{i=1,2}Q_{\phi_{i,\text{targ}}}(s',a'(s'))
$$

两个 online critic 都向同一个 `y` 回归：

$$
L(\phi_i)=\mathbb{E}_{(s,a,r,s',d)}\left[\left(Q_{\phi_i}(s,a)-y\right)^2\right],\quad i=1,2
$$

**经验**：

- “双 Q 取最小”不是简单的模型集成。它把 Q 值往保守方向压，牺牲一点乐观性来换取稳定性。
- 两个 critic 必须独立初始化。如果共享参数，取 min 就失去意义。
- 两个 critic 使用同一批数据、同一个 target，但各自更新自己的优化器。
- 计算 actor loss 时只用 `Q1`，这是 Spinning Up 和原论文的做法；`Q2` 只参与 target 计算。

### 2.2 Target policy smoothing

给 target actor 输出的下一动作加噪声，并截断：

$$
a'(s')=\operatorname{clip}\left(\mu_{\theta_{\text{targ}}}(s')+\operatorname{clip}(\epsilon,-c,c),a_{Low},a_{High}\right),\quad \epsilon\sim\mathcal{N}(0,\sigma^2)
$$

Spinning Up 默认 `sigma=0.2`、`c=0.5`（归一化动作空间）。

**经验**：

- 这不是探索噪声。它只用于计算 critic 的 target，训练 actor 时执行的是纯 `mu(s)`。
- 它的作用是让 critic 在 target 动作附近的一小片区域给出相近的 Q 值，减少“尖峰被 actor 利用”的机会。
- 噪声要截断两次：先截断噪声幅度到 `[-c, c]`，再把加噪后的动作截断到环境动作范围。
- **单位最容易写错**。Spinning Up 的 `sigma` 和 `c` 定义在 `[-1, 1]` 的归一化动作空间；本项目的 actor 直接输出环境动作（Pendulum 为 `[-2, 2]`），所以内部要乘以 `action_scale = (high - low) / 2`。如果忘了换算，Pendulum 上的平滑噪声会小一半。

### 2.3 Delayed policy update

每次梯度更新都更新两个 critic，但只有满足：

$$
j\bmod\text{policy\_delay}=0
$$

时才更新 actor 和三个 target 网络。默认 `policy_delay=2`。

**经验**：

- 计数对象是“`update()` 被调用的次数”，不是环境步数，也不是 episode 数。
- 第一个 actor 更新发生在第 2 次 `update()`，而不是第 1 次。这符合“先让 critic 学两步”的直觉。
- actor 更新后再软更新 target，保证 target 的变化频率与 actor 一致。
- 延迟更新让 critic 有机会先收敛一点，actor 的梯度方向更可靠。

## 3. 完整 pipeline

```text
初始化 actor / target_actor / Q1 / Q2 / target_Q1 / target_Q2
        │
        ▼
每个 episode：
  reset 环境
        │
        ▼
  每个时间步：
    a = clip(actor(s) + GaussianNoise, low, high)
    执行 a，得到 (s', r, terminated, truncated)
    buffer.add(s, a, r, s', terminated)        # 注意不是 truncated
        │
        ▼
    if buffer.size >= minimal_size:
        batch = buffer.sample(batch_size)
        计算 a' = smooth(target_actor(s'))
        y = r + gamma * (1 - done) * min(target_Q1(s',a'), target_Q2(s',a'))
        更新 Q1、Q2
        update_count += 1
        if update_count % policy_delay == 0:
            更新 actor（最大化 Q1(s, actor(s))）
            软更新 target_actor、target_Q1、target_Q2
        │
        ▼
  episode 结束，记录带探索噪声的回报
        │
        ▼
训练结束：关闭噪声，跑若干 episode 得到 evaluation return
```

## 5. 关键实现细节

### 5.1 六个网络与两个优化器

TD3 有 6 个网络，但只有 3 个需要优化器：

```text
optimizer：actor
optimizer：critic_1
optimizer：critic_2

不优化：target_actor、target_critic_1、target_critic_2
```

target 网络只通过 `soft_update()` 从 online 网络复制参数。

### 5.2 软更新

$$
\theta_{\text{targ}}\leftarrow(1-\tau)\theta_{\text{targ}}+\tau\theta
$$

代码使用原地操作：

```python
target_param.data.mul_(1 - self.tau)
target_param.data.add_(self.tau * online_param.data)
```

不要对 target 参数直接做带梯度的运算，否则它们会被卷入计算图。

`tau=0.005` 意味着 target 大约需要几百次更新才能明显跟上 online 网络。这是稳定性的来源之一。

### 5.3 更新 actor 时冻结 critic

actor loss 是：

$$
L_{\text{actor}}=-\mathbb{E}\left[Q_1(s,\mu(s))\right]
$$

反向传播时，梯度会经过 `Q1`。但我们只更新 actor，不更新 critic。Spinning Up 的做法是临时把 critic 参数的 `requires_grad` 设为 `False`：

```python
for p in self.critic_1.parameters():
    p.requires_grad_(False)
...
for p in self.critic_1.parameters():
    p.requires_grad_(True)
```

这样做有两个好处：

- 不计算无用的 critic 梯度，节省计算。
- 避免 critic 参数上残留上一轮的梯度。

本实现用 `try/finally` 保证即使反向传播出错也会恢复 `requires_grad`。

### 5.4 动作边界与噪声单位

`networks.py` 中的 actor 输出：

```python
action_bias + action_scale * tanh(...)
```

Pendulum 的动作范围是 `[-2, 2]`，因此：

```text
action_scale = 2
action_bias  = 0
```

两种噪声的单位不同：

| 噪声 | 定义空间 | 代码处理 |
| --- | --- | --- |
| 探索噪声 | 环境动作单位 | `action + sigma * randn` |
| target smoothing | 归一化动作单位 | 先乘 `action_scale`，再加到动作上 |

最终所有动作都要裁剪到 `[action_low, action_high]`。

### 5.5 `terminated` 与 `truncated`

Gymnasium 返回：

```python
next_state, reward, terminated, truncated, info = env.step(action)
```

- `terminated=True`：环境真正终止（例如倒立摆倒下、任务成功）。
- `truncated=True`：达到时间上限或外部截断。

训练循环用二者结束 episode：

```python
done = terminated or truncated
```

但写入 buffer 时只能用 `terminated`：

```python
replay_buffer.add(state, action, reward, next_state, terminated)
```

原因：Pendulum 每 200 步被 `truncated`，但摆并没有“死亡”，下一状态仍然有价值。如果把 truncated 当成 terminal，critic 会认为每个 episode 的最后一步之后价值为零，产生系统性偏差。

### 5.6 探索噪声

行为动作：

$$
a_{\text{behavior}}=\operatorname{clip}(\mu(s)+\sigma\epsilon,a_{Low},a_{High}),\quad \epsilon\sim\mathcal{N}(0,I)
$$

- `sigma=0.1` 是针对 Pendulum 动作范围 `[-2, 2]` 的取值。
- 训练时加噪声是为了覆盖状态-动作空间；评估时关闭。
- TD3 不依赖 OU 噪声。OU 的时间相关性可能让动作更平滑，但也会降低探索的独立性；Spinning Up 默认使用独立高斯噪声。
- 如果发现早期探索不足，可以增大 `EXPLORATION_SIGMA`；如果后期回报抖动明显，可以尝试随训练衰减噪声（本实现未加入，保持与 Spinning Up 一致）。

### 5.7 评估协议

训练回报包含探索噪声，不能直接代表策略质量。本实现训练结束后：

1. 关闭探索噪声；
2. 使用固定的评估种子 `EVAL_SEED` 重置环境；
3. 跑 `EVAL_EPISODES=20` 个 episode；
4. 报告均值、标准差和最佳值。

固定评估种子的意义：比较不同训练种子时，所有模型面对同一批初始状态，减少评估方差。

Pendulum 的初始状态是随机的，不同初始角度/速度的难度差异很大，因此单个 episode 的评估回报波动可能达到几十甚至上百。**不要用 1 个评估 episode 下结论。**

| --- | ---: | ---: | --- |
| actor lr | `1e-3` | `1e-3` | 一致 |
| critic lr | `1e-3` | `1e-3` | 一致 |
| hidden | `256 x 2` | `128 x 2` | Pendulum 状态维度低，128 足够 |
| gamma | `0.99` | `0.99` | 一致 |
| tau / polyak | `0.995` | `0.005` 的 tau | 注意两种写法含义相反 |
| policy delay | `2` | `2` | 一致 |
| target noise | `0.2` | `0.2` | 归一化动作单位 |
| noise clip | `0.5` | `0.5` | 归一化动作单位 |
| act noise | `0.1` | `0.1` | Spinning Up 在归一化空间；本项目在环境动作单位 |

**关于 `tau` 和 `polyak`**：Spinning Up 参数名 `polyak=0.995`，更新写作 `target = polyak * target + (1-polyak) * online`；本仓库其他算法把 `TAU` 定义为 online 的权重，更新写作 `target = (1-tau) * target + tau * online`。两者数值上 `tau = 1 - polyak`。阅读不同代码时一定要先确认公式，不能只看变量名。

### 7.3 如何解读

1. **两者的最终确定性评估表现接近**（TD3 `-124.9`，DDPG `-126.9`）。Pendulum 是一个相对简单的连续控制任务，200 回合后两种算法都能学到“把摆甩起来并保持”的策略，差距不会像在高维机器人任务上那么明显。
2. **TD3 的训练回报更好且更稳定**：末 10 回合均值 `-169.9 ± 12.0`，DDPG 为 `-206.7 ± 25.7`。训练回报包含探索噪声，因此这个差距主要反映“策略 + 探索”的整体表现，但也说明 TD3 对超参数和随机种子的敏感度更低。
3. **评估标准差很大是正常的**：同一个策略在不同初始状态下的回报差异很大，有的初始状态几乎从最低点开始，有的接近倒立位置。评估均值跨种子的标准差（TD3 `±3.9`）小，说明不同训练种子得到的策略水平接近。
4. **这不是受控消融实验**：两个文件夹的超参数不同（gamma、hidden、学习率、buffer 大小）。这里比较的是“两套默认配置”的实际表现，不能把差距全部归因于 TD3 的三项改进。要做严格消融，应固定其他超参数，只切换 double-Q / smoothing / delay。
5. **单个种子不能证明算法优劣**。上表已经给出 3 个种子的均值和标准差；更严谨的实验应使用 5 个以上种子，并报告置信区间。

### 7.4 训练曲线特征

典型的 TD3 Pendulum 曲线会出现：

- 前 20~40 回合回报在 `-1200` 到 `-1500` 附近，基本是随机策略水平；
- 大约 50 回合后快速上升到 `-200` 左右；
- 之后在 `-100` 到 `-250` 之间波动；
- 训练最佳 episode 可以接近 `0`，但平均回报不会一直保持在那里。

这种“先平后升、后期波动”的形状是正常的。不要因为某个 episode 突然变差就认为代码有 bug，应看移动平均趋势。

## 8. 常见坑与排错

### 8.1 动作越界

**现象**：环境报错，或策略学到边界动作后不再改善。

**检查**：

```python
action = agent.take_action(state, explore=True)
print(action.shape, action.min(), action.max())
```

Pendulum 合法范围是 `[-2, 2]`。actor 的 `tanh` 输出已经映射到该范围，但加噪声后必须再裁剪一次。

### 8.2 target smoothing 噪声单位错误

**现象**：训练能跑，但 smoothing 几乎不起作用，或动作被大面积裁剪。

**检查**：`TARGET_NOISE` / `NOISE_CLIP` 是否按归一化空间定义，并在 `smooth_target_action()` 中乘了 `action_scale`。

### 8.3 延迟更新计数错误

**现象**：actor 每个 step 都在更新，TD3 退化成 DDPG；或 actor 几乎不更新。

**检查**：

```python
assert 1 <= config.POLICY_DELAY
# 每 policy_delay 次 update，actor 更新一次
```

`update_count` 应该在每次 `update()` 末尾自增，且自增后判断 `% policy_delay == 0`。

### 8.4 把 truncated 当成 terminal

**现象**：critic 的 Q 值整体偏低，策略在 episode 末尾表现得“不想继续”。

**检查**：`replay_buffer.add(...)` 的最后一个参数必须是 `terminated`，不是 `done`。

### 8.5 忘记冻结 critic

**现象**：一般不会报错，但计算量略大；某些实现中 critic 会积累无用梯度。

**检查**：actor loss 反传前，critic 的 `requires_grad` 是否为 `False`。

### 8.6 评估用了探索噪声

**现象**：评估回报远低于训练回报，或评估结果抖动很大。

**检查**：评估时调用 `agent.take_action(state, explore=False)`。

### 8.7 buffer 太小或 `MINIMAL_SIZE` 太大

**现象**：200 回合内几乎没有更新，回报一直是随机水平。

**检查**：`BUFFER_SIZE` 应远大于 `MINIMAL_SIZE` 和 `BATCH_SIZE`；Pendulum 的 200 回合共 4 万步，`MINIMAL_SIZE=1000` 是合理的。

## 9. 与 DDPG、SAC 的关系

| 维度 | DDPG | TD3 | SAC |
| --- | --- | --- | --- |
| 策略 | 确定性 | 确定性 | 随机高斯 |
| Critic 数量 | 1 | 2 | 2 |
| Q 值高估处理 | 无 | 双 Q 取最小 | 双 Q 取最小 |
| 探索方式 | 外加噪声 | 外加噪声 | 策略自带随机性 + 熵 |
| Target 稳定性 | 软更新 | 软更新 + smoothing + 延迟 | 软更新 |
| 适用场景 | 连续控制 baseline | 连续控制，稳定版 DDPG | 连续控制，样本效率高、稳定性好 |

学习顺序建议：DDPG → TD3 → SAC。

- 先理解 DDPG 的确定性 actor、Q critic 和 target 网络；
- 再看 TD3 如何在**不改动 actor 结构**的前提下，用三个技巧提升稳定性；
- 最后看 SAC 如何把确定性策略换成随机策略，并用熵正则实现自动探索。

## 10. 可继续做的实验

1. **消融实验**：固定其他超参数，分别关闭 double-Q、smoothing、delay，观察 3 个种子下的评估均值和方差。
2. **噪声敏感性**：比较 `EXPLORATION_SIGMA` 为 `0.05 / 0.1 / 0.2` 的结果。
3. **延迟系数**：比较 `POLICY_DELAY` 为 `1 / 2 / 4`。`1` 等价于去掉延迟更新。
4. **target smoothing 强度**：比较 `TARGET_NOISE` 为 `0.0 / 0.2 / 0.5`，观察 Q 值曲线和评估回报。
5. **训练更长**：把 `NUM_EPISODES` 提高到 `500`，观察评估回报是否继续提升，以及是否出现后期崩溃。
6. **换环境**：在 `HalfCheetah`、`Walker2d`、`Hopper` 等 MuJoCo 连续控制任务上测试，才能更明显地看出 TD3 相对 DDPG 的优势。

## 11. 一句话总结

TD3 的核心不是“更复杂的网络”，而是**让 critic 的 target 更保守、更平滑，并让 actor 更新得更慢**。理解 `calc_target()` 和 `update()` 里的更新顺序，就理解了 TD3 的全部关键设计。

## 在算法推进线上的位置

- **从哪来**：09 DDPG 的三个已知弱点——Q 值高估、target 尖峰、actor 更新过频。
- **到哪去**：11 SAC 是同一代的另一条路线，保留双 Q、换成最大熵随机策略；本仓库之外的 model-based/offline RL 则从另一个维度继续推进。
- **一句话记住**：TD3 是 DDPG 的“稳定性补丁包”，它没有换框架，只是让 target 更保守、actor 更慢。
