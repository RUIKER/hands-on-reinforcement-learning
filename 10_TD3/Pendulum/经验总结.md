# 10 TD3 · Pendulum 案例经验总结

> **算法编号**：10 / 11 · Pendulum 案例
> **算法家族**：off-policy 确定性 actor-critic
> 更完整的原理、消融建议和算法对比见上级目录的 [`../经验总结.md`](../经验总结.md)。本文件聚焦 `Pendulum` 这套 pipeline 的实现细节和实测结果。

## 本案例中的四个问题

### 这个算法的特点是什么

在 Pendulum 上，TD3 用确定性 actor + 双 Q critic + replay buffer + target 网络；每个环境步更新两个 critic，每 2 次更新才更新一次 actor 和三个 target 网络；target 动作加截断噪声。

### 它针对前驱算法的哪些缺陷

它针对 DDPG 在 Pendulum 上暴露的三个问题：单 critic 的高估、target 动作附近的 Q 尖峰、actor 跟着不准确 critic 频繁更新。双 Q、smoothing、延迟更新分别对应这三点。

### 局限性在什么地方

本案例中 TD3 的 3 个种子末 10 回合训练回报为 `-169.9 ± 12.0`，比 DDPG 的 `-206.7 ± 25.7` 更稳；但确定性评估均值 `-124.9` 与 DDPG 的 `-126.9` 很接近。Pendulum 太简单，不能据此认为 TD3 在所有任务上都大幅优于 DDPG；它仍是确定性策略，探索靠外加噪声。

### 典型应用场景有哪些

连续控制中 DDPG 不稳定的场景、机械臂/倒立摆/locomotion、工业连续控制；也适合作为 DDPG 的受控对照实验。

> 以下为本案例的实现细节、实验结果与排错记录。

## 1. 这份实现做了什么

TD3 在 DDPG 的基础上加入三项改进：

```text
双 critic               → 用 min(Q1_target, Q2_target) 计算 Bellman target
target policy smoothing → 给 target actor 的下一动作加截断噪声
delayed policy update   → 每 policy_delay 次 critic 更新，才更新一次 actor
```

代码中的对应位置：

| 改进 | 位置 |
| --- | --- |
| 双 critic | `agents.py` 的 `critic_1` / `critic_2` 及两个 target |
| clipped double-Q | `agents.py` 的 `calc_target()` 中 `torch.min(next_q_1, next_q_2)` |
| target smoothing | `noise.py` 的 `smooth_target_action()` |
| delayed update | `agents.py` 的 `update_count % policy_delay == 0` |

## 2. 数据流

```text
env.reset()
  │
  ▼
actor(s) + 高斯噪声 → 裁剪到 [-2, 2] → env.step()
  │
  ▼
(s, a, r, s', terminated) → ReplayBuffer
  │
  ▼
buffer.size >= 1000
  │
  ▼
sample(batch=100)
  │
  ▼
a' = smooth(target_actor(s'))
y  = r + γ(1-d) min(target_Q1(s',a'), target_Q2(s',a'))
  │
  ├─ 更新 Q1、Q2
  │
  └─ 每 2 次更新：
       actor_loss = -Q1(s, actor(s))
       软更新 target_actor、target_Q1、target_Q2
```

## 3. 为什么这样写

### 3.1 `calc_target()` 放在 `no_grad()` 里

target 只是监督信号，不应该对 target 网络求梯度。所有 target 计算都用：

```python
with torch.no_grad():
    ...
```

### 3.2 两个 critic 回归同一个 target

```python
q_target = self.calc_target(...)
critic_loss = mse(critic_1(s, a), q_target) + mse(critic_2(s, a), q_target)
```

注意：`q_target` 只计算一次，两个 critic 共用。不要分别用各自的 target 网络算两个不同的 target，否则 clipped double-Q 的“保守估计”含义就被破坏了。

### 3.3 actor 只用 Q1 更新

```python
actor_loss = -self.critic_1(states, self.actor(states)).mean()
```

Q2 只参与 target 的 `min`。这是 Spinning Up 和原论文的实现。也可以改成 `-min(Q1, Q2)`，但会改变梯度行为，不属于标准 TD3。

### 3.4 冻结 critic 的时机

```python
critic_1.requires_grad_(False)
critic_2.requires_grad_(False)
try:
    actor_loss.backward()
finally:
    critic_1.requires_grad_(True)
    critic_2.requires_grad_(True)
```

`try/finally` 是防御性写法：即使反向传播抛出异常，也不会让 critic 永久处于冻结状态。

### 3.5 `update_count` 从 1 开始计数

```python
self.update_count += 1
if self.update_count % self.policy_delay == 0:
```

第一次 `update()` 只更新 critic；第二次才更新 actor。若把判断写在自增之前，第一次就会更新 actor，延迟效果会差一步。对于 4 万次更新，这一步的差异可以忽略，但语义上应保持“先 critic 后 actor”。

## 4. 超参数选择

| 参数 | 值 | 理由 |
| --- | ---: | --- |
| `ACTOR_LR` | `1e-3` | Spinning Up 默认；延迟更新后 actor 更新不频繁，可以稍大 |
| `CRITIC_LR` | `1e-3` | 与 actor 相同，TD3 原论文设置 |
| `HIDDEN_DIM` | `128` | Pendulum 状态维度为 3，128 足够 |
| `GAMMA` | `0.99` | 200 步的 episode，需要看得稍远 |
| `TAU` | `0.005` | target 缓慢跟随，约几百次更新后追上 |
| `POLICY_DELAY` | `2` | 原论文默认 |
| `TARGET_NOISE` | `0.2` | 原论文默认（归一化动作空间） |
| `NOISE_CLIP` | `0.5` | 原论文默认（归一化动作空间） |
| `EXPLORATION_SIGMA` | `0.1` | 环境动作单位，约为动作范围的 2.5% |
| `BATCH_SIZE` | `100` | Spinning Up 默认 |
| `BUFFER_SIZE` | `100000` | 200 回合共 4 万步，足够覆盖训练数据 |

**注意**：DDPG 教程使用 `critic_lr=3e-3`、`actor_lr=3e-4`，TD3 使用相同学习率 `1e-3`。不要把 DDPG 的学习率直接照搬到 TD3，也不要因为“critic 更难学”就盲目调大 critic 学习率；延迟更新已经改变了两个网络的相对更新频率。

## 5. 实测结果

设置：`Pendulum-v1`，200 回合 × 200 步，固定 seed，评估 20 个 episode（确定性策略、固定评估种子）。

### TD3

| 种子 | 末 10 回合训练回报 | 评估均值 | 评估标准差 | 评估最佳 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | `-153.517` | `-119.559` | `82.670` | `-0.086` |
| 1 | `-174.176` | `-128.614` | `84.536` | `-1.553` |
| 2 | `-182.090` | `-126.519` | `84.090` | `-6.048` |
| **均值 ± 标准差** | **`-169.928 ± 12.046`** | **`-124.897 ± 3.871`** | — | — |

### DDPG 对照（各自默认配置）

| 种子 | 末 10 回合训练回报 | 评估均值 |
| ---: | ---: | ---: |
| 0 | `-241.920` | `-125.962` |
| 1 | `-181.082` | `-125.308` |
| 2 | `-197.232` | `-129.302` |
| **均值 ± 标准差** | **`-206.745 ± 25.732`** | **`-126.857 ± 1.749`** |

### 解读

- TD3 的训练回报更好、跨种子波动更小（`±12.0` vs `±25.7`）。
- 两者的确定性评估均值非常接近（`-124.9` vs `-126.9`）。Pendulum 太简单，200 回合足以让 DDPG 也学到不错策略，TD3 的优势主要体现在训练稳定性和对超参数的鲁棒性上。
- 两套配置的超参数不同，因此这不是严格消融实验。
- 评估标准差约 `80`，说明不同初始状态难度差异很大；跨种子的评估均值标准差只有约 `4`，更能反映算法水平。

## 6. 调试记录与建议

### 6.1 第一次跑不通时

把 `config.py` 改成：

```python
NUM_EPISODES = 1
MINIMAL_SIZE = 1
BATCH_SIZE = 8
```

然后确认：

```text
state.shape = (3,)
action.shape = (1,)
action ∈ [-2, 2]
buffer.size() 正常增长
update_count 正常增长
```

### 6.2 回报一直上不去

按顺序检查：

1. `EXPLORATION_SIGMA` 是否太小（探索不足）或太大（动作太乱）。
2. `TAU` 是否太大，导致 target 抖动。
3. `actor_lr` / `critic_lr` 是否过大，导致 loss 爆炸。
4. `MINIMAL_SIZE` 是否太大，200 回合内根本没开始学习。
5. buffer 写入的 `done` 是否误用了 `truncated`。

### 6.3 回报先升后崩

常见原因：

- actor 学习率过大，策略更新过猛；
- 双 Q 仍然不足以抑制高估；
- 探索噪声在后期太大，把已经学好的策略打乱。

可以尝试：降低 `ACTOR_LR`、增大 `POLICY_DELAY`、让探索噪声随训练衰减。当前实现为了保持和 Spinning Up 一致，没有加入噪声衰减。

### 6.4 评估和训练回报差距很大

这是正常的：训练时执行 `actor(s) + noise`，评估时执行纯 `actor(s)`。比较算法时应使用**同一评估协议**，不要拿 A 的训练回报和 B 的评估回报比较。

## 7. 与 `practice.py` 的关系

## 在算法推进线上的位置

- **从哪来**：09 DDPG 在 Pendulum 上暴露的训练波动、Q 值高估和 target 尖峰。
- **到哪去**：11 SAC 保留双 Q、换成最大熵随机策略；本案例也可以作为 SAC 的对照 baseline。
- **一句话记住**：TD3 在本案例中把训练回报的跨种子波动从 DDPG 的 `±25.7` 降到 `±12.0`，但最终评估水平接近——稳定性是它的主要收益。
