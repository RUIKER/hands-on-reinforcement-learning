# 04 REINFORCE 经验总结

> **算法编号**：04 / 11
> **算法家族**：on-policy、Monte Carlo 策略梯度
> **前驱算法**：03 DQN / Double DQN / Dueling DQN（价值型分支）
> **后继算法**：05 Actor-Critic
> **一句话定位**：不再学 Q 值再取 `argmax`，而是直接参数化策略并对期望回报做梯度上升；它开启了策略梯度分支，也用完整回报换来了高方差。

## 算法定位：四个问题

### 这个算法的特点是什么

REINFORCE 直接学习随机策略 `π_θ(a|s)`，用一整条 episode 的折扣回报 `G_t` 做策略梯度：

$$
\nabla_\theta J(\theta)=\mathbb{E}_{\pi_\theta}\left[\sum_t G_t\nabla_\theta\log\pi_\theta(a_t|s_t)\right]
$$

它的几个标志：

- **随机策略**：离散动作输出 `Categorical` 概率，按概率采样；连续动作可输出高斯分布。
- **Monte Carlo 回报**：`G_t = r_t + γG_{t+1}`，必须等 episode 结束才能算。
- **on-policy**：数据由当前策略产生，更新后旧数据基本不再使用，因此不需要 replay buffer。
- **无 critic、无自举**：只用回报，不学价值函数。

### 它针对前驱算法的哪些缺陷

- **价值型方法只能间接得到策略**：DQN 系列先学 `Q(s,a)`，再对有限动作取 `argmax`，天然只适合离散动作，也无法表示“同一状态按概率随机选动作”的最优策略。
- **连续/高维动作难以 `argmax`**：REINFORCE 直接输出动作分布参数，连续动作可以用高斯策略。
- **价值型方法的策略改进是隐式的**：REINFORCE 直接对“期望回报”求梯度，目标更直接。

### 局限性在什么地方

- **方差大**：用整条轨迹的 `G_t` 做权重，回报的随机性会直接放大梯度噪声；没有 baseline 时尤其明显。
- **必须等完整 episode**：不能在线逐步更新，长 episode 或持续任务不友好。
- **样本效率低**：on-policy，数据用一次就丢；通常需要大量 episode。
- **对回报尺度/学习率敏感**：回报大的任务梯度也大，容易更新过猛；回报小时学得慢。
- **探索会塌缩**：策略可能过早收敛到某个动作，之后很难恢复。
- **没有 credit assignment 之外的机制**：所有时间步都用同一个回报加权，无法区分“哪一步真正关键”。

### 典型应用场景有哪些

- episodic 的简单控制任务（CartPole、简单游戏）和策略搜索 baseline。
- 连续动作任务的高斯策略版本（作为 DDPG/SAC 之前的策略梯度基线）。
- 教学：理解 `log π`、回报加权、on-policy 采样和方差问题。
- 现代策略梯度方法的祖先：PPO、GRPO 等都可以看作“REINFORCE + 重要性采样/裁剪/基线”的演化。

## 1. 项目目标

本项目使用 REINFORCE（Monte Carlo Policy Gradient）算法训练 `CartPole-v1` 环境。

REINFORCE 与 DQN 的核心区别是：

- DQN 学习动作价值函数 `Q(s, a)`。
- REINFORCE 直接学习策略 `pi(a|s)`。
- DQN 通常可以从 replay buffer 中反复采样。
- REINFORCE 是 on-policy 算法，一般收集完整 episode 后更新一次策略。

## 3. REINFORCE 的训练流程

每个 episode 的流程是：

```text
reset 环境
    ↓
根据策略概率采样动作
    ↓
执行动作并获得 reward
    ↓
保存 state、action、reward
    ↓
直到 episode 结束
    ↓
从后往前计算回报 G_t
    ↓
根据策略梯度更新 policy network
```

与 DQN 不同，REINFORCE 不会在每一步都更新网络，而是在一个完整 episode 结束后统一更新。

## 4. 策略网络

`PolicyNet` 的输入是状态，输出是每个离散动作的概率：

```text
state
  -> Linear
  -> ReLU
  -> Linear
  -> Softmax
  -> [P(action=0), P(action=1), ...]
```

CartPole 有两个离散动作，因此网络输出形状为：

```text
[batch_size, 2]
```

输出概率满足：

$$
\sum_a \pi(a|s)=1
$$

动作不是直接选择概率最大的动作，而是按照概率分布随机采样：

```python
action_dist = torch.distributions.Categorical(probs)
action = action_dist.sample()
```

这是 REINFORCE 的重要特征。如果使用 `argmax()`，就变成了确定性选择，无法正确表达策略梯度中的随机策略。

## 5. REINFORCE 更新公式

REINFORCE 使用从时间步 `t` 开始的累计折扣回报：

$$
G_t=r_t+\gamma r_{t+1}+\gamma^2r_{t+2}+\cdots
$$

从 episode 末尾向前计算时，可以使用：

$$
G_t=r_t+\gamma G_{t+1}
$$

代码对应：

```python
G = self.gamma * G + reward
```

策略梯度目标为：

$$
\nabla J(\theta)
=
\mathbb{E}\left[G_t\nabla\log\pi_\theta(a_t|s_t)\right]
$$

因为 PyTorch 默认执行最小化，所以将 loss 写成负号：

$$
Loss=-G_t\log\pi_\theta(a_t|s_t)
$$

代码逻辑为：

```python
log_prob = action_dist.log_prob(action)
loss = -log_prob * G
loss.backward()
```

一个 episode 内多次调用 `backward()`，梯度会累积；episode 结束后再执行一次：

```python
self.optimizer.step()
```

因此整个 episode 的所有时间步都会共同影响策略更新。

## 6. 为什么要使用 `Categorical.log_prob`

原始示例使用：

```python
log_prob = torch.log(policy_net(state).gather(1, action))
```

这个写法可以表达数学公式，但手动对概率取 `log` 可能遇到数值稳定性问题。

当前使用：

```python
probs = self.policy_net(state)
action_dist = torch.distributions.Categorical(probs)
log_prob = action_dist.log_prob(action)
```

由 PyTorch 的分布对象负责计算 log probability，更清晰，也更稳定。

## 7. Gymnasium API 适配

当前项目使用 Gymnasium，不再使用旧版 Gym API。

环境重置：

```python
state, info = env.reset()
```

环境交互：

```python
next_state, reward, terminated, truncated, info = env.step(action)
done = terminated or truncated
```

其中：

- `terminated`：任务本身达到终止条件。
- `truncated`：达到时间限制等外部终止条件。
- `done`：训练循环中统一使用的结束标志。

环境名称使用：

```python
ENV_NAME = 'CartPole-v1'
```

而不是已经过时的 `CartPole-v0`。

## 8. On-policy 的含义

REINFORCE 是 on-policy 算法：

```text
当前策略采样 episode
    ↓
使用这些数据更新当前策略
    ↓
旧数据通常不再重复使用
```

因此 REINFORCE 不需要 DQN 中的 replay buffer。

当前训练器会把一个完整 episode 保存到 `transition_dict`：

```python
{
    'states': [],
    'actions': [],
    'next_states': [],
    'rewards': [],
    'dones': []
}
```

episode 结束后调用：

```python
agent.update(transition_dict)
```

`next_states` 和 `dones` 在最基础的 REINFORCE 更新中并不是必须的，但保留它们可以让 transition 结构更统一，方便以后扩展 Actor-Critic 等算法。

### 9.3 Gymnasium 返回值数量变化

旧代码使用：

```python

```

这会导致状态实际上变成 `(observation, info)`，并且 `step()` 解包数量错误。

### 9.4 状态 tensor 构造效率问题

原始代码使用：

```python

```

当 `state` 本身是 NumPy 数组时，这会产生性能警告。

当前使用：

```python

    np.asarray(state),
    dtype=torch.float32,
    device=self.device,
).unsqueeze(0)
```

这样可以更直接地从 NumPy 数组创建 tensor。

### 9.5 短测试时移动平均窗口过大

如果只训练 1 个 episode，却直接使用窗口大小为 9 的移动平均，绘图函数可能产生长度不匹配或异常。

当前绘图逻辑是：

```python
    直接绘制原始回报
```

## 12. 后续可改进方向

### 12.1 使用回报标准化

REINFORCE 的方差通常较大，可以对一整个 episode 的 `G_t` 做标准化：

$$
\hat{G}_t=\frac{G_t-\text{mean}(G)}{\text{std}(G)+\epsilon}
$$

这样通常可以提高训练稳定性。

### 12.2 使用 Baseline

可以引入状态价值网络 `V(s)`，使用：

$$
A_t=G_t-V(s_t)
$$

这会从 REINFORCE 逐步过渡到 Actor-Critic。

### 12.3 完善随机种子

当前已经设置 Python、NumPy 和 PyTorch 的随机种子。为了更好地复现实验，还可以在第一次环境重置时显式传入：

```python
env.reset(seed=config.SEED)
```

如果使用 CUDA，还可以根据需要设置 CUDA 的确定性选项。

### 12.4 多随机种子实验

REINFORCE 的结果波动较大，建议使用多个 seed 比较：

- 最终平均回报。
- 最佳回报。
- 回报曲线的波动。
- 达到某个回报阈值所需的 episode 数。

## 13. 总结

这个项目最重要的三个理解点是：

1. 策略网络输出的是动作概率，而不是 Q 值。
2. REINFORCE 使用完整 episode 的折扣回报更新策略。
3. REINFORCE 是 on-policy 算法，训练数据由当前策略产生并在 episode 结束后使用。
